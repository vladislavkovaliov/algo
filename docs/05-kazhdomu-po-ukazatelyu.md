# Глава 5. По указателю на каждый массив

Третье большое семейство. Здесь **два массива** (или две строки), и у каждого свой указатель.

```text
i
↓
[1, 3, 5]
[2, 4, 6]
       ↑
       j
```

Указатели движутся слева направо, но каждый — по своему массиву.

---

## 5.1. Главная идея: сравниваем текущие элементы

На каждом шаге мы смотрим на `a[i]` и `b[j]` и отвечаем на вопрос:

> **Какой из этих двух элементов «отстаёт»?**

- Если `a[i] < b[j]`, то `a[i]` меньше любого элемента, который ещё может появиться в `b` справа. Значит, с `a[i]` уже всё понятно — двигаем `i`.
- Если `a[i] > b[j]`, симметрично двигаем `j`.
- Если равны — нашли общий элемент (или обработали совпадение), двигаем оба.

Это работает благодаря **отсортированности**. Если массивы не отсортированы, сравнение «меньше» ничего не говорит о будущих элементах.

## 5.2. Задача 11: MergeSortedArrays

### Условие

Даны два отсортированных массива. Слить их в один отсортированный.

```text
Вход:  [1, 3, 5] и [2, 4, 6]
Выход: [1, 2, 3, 4, 5, 6]
```

### Идея

Смотрим на начала обоих массивов. Берём меньший элемент и двигаем указатель того массива, откуда взяли. Когда один массив закончился, дописываем остаток другого.

### Код

```typescript
export function mergeSortedArrays(nums1: number[], nums2: number[]): number[] {
    const result: number[] = [];
    let i = 0;
    let j = 0;

    while (i < nums1.length && j < nums2.length) {
        if (nums1[i] < nums2[j]) {
            result.push(nums1[i]);
            i++;
        } else {
            result.push(nums2[j]);
            j++;
        }
    }

    while (i < nums1.length) {
        result.push(nums1[i]);
        i++;
    }

    while (j < nums2.length) {
        result.push(nums2[j]);
        j++;
    }

    return result;
}
```

### Разбор

Вход: `[1, 3, 5]` и `[2, 4, 6]`.

| Шаг | i | j | nums1[i] | nums2[j] | Берём | Результат |
|-----|---|----|----------|----------|-------|-----------|
| 0 | 0 | 0 | 1 | 2 | 1 | `[1]` |
| 1 | 1 | 0 | 3 | 2 | 2 | `[1, 2]` |
| 2 | 1 | 1 | 3 | 4 | 3 | `[1, 2, 3]` |
| 3 | 2 | 1 | 5 | 4 | 4 | `[1, 2, 3, 4]` |
| 4 | 2 | 2 | 5 | 6 | 5 | `[1, 2, 3, 4, 5]` |
| 5 | 3 | 2 | — | 6 | остаток nums2 | `[1, 2, 3, 4, 5, 6]` |

Ответ: `[1, 2, 3, 4, 5, 6]`.

### Зачем два цикла после основного

Основной цикл работает, пока **оба** массива не закончились. Как только один закончился, сравнивать не с чем — оставшиеся элементы второго уже отсортированы и больше (или равны) всех, что мы взяли. Их можно просто дописать.

Это классическая ошибка: забыть про остаток. Тогда, например, `[1, 2, 3]` + `[4, 5, 6]` потеряет вторую половину.

### Почему `<`, а не `<=`

При равенстве порядок между равными элементами не важен для сортировки. В коде при равенстве берётся элемент из второго массива (`else`). Это допустимо.

Если бы требовалась **устойчивость** (сохранять относительный порядок равных элементов из первого массива), нужно было бы `<=` и брать из первого. Для этой задачи не важно.

### Сложность

- Время: O(n + m), где `n` и `m` — длины массивов.
- Память: O(n + m) на результат.

### Связь с сортировкой слиянием

Этот алгоритм — центральная часть **merge sort**. Сортировка слиянием делит массив пополам, сортирует половины и сливает их этим способом. Понимание задачи 11 — шаг к пониманию сортировки слиянием.

## 5.3. Задача 12: IntersectionOfTwoArrays

### Условие

Даны два отсортированных массива. Найти числа, которые есть в обоих, **без повторов** в ответе.

```text
Вход:  [1, 1, 2, 2] и [2, 2]
Выход: [2]
```

### Идея

Двигаем указатели по правилу «меньший отстаёт». При равенстве добавляем число, но только если оно ещё не добавлено.

### Код

```typescript
export function intersectionOfTwoArrays(nums1: number[], nums2: number[]): number[] {
    const result: number[] = [];
    let i = 0;
    let j = 0;

    while (i < nums1.length && j < nums2.length) {
        if (nums1[i] < nums2[j]) {
            i++;
        } else if (nums1[i] > nums2[j]) {
            j++;
        } else {
            if (result.length === 0 || result[result.length - 1] !== nums1[i]) {
                result.push(nums1[i]);
            }
            i++;
            j++;
        }
    }

    return result;
}
```

### Разбор

Вход: `[1, 1, 2, 2]` и `[2, 2]`.

| Шаг | i | j | nums1[i] | nums2[j] | Сравнение | Действие | Результат |
|-----|---|----|----------|----------|-----------|----------|-----------|
| 0 | 0 | 0 | 1 | 2 | 1 < 2 | i++ | `[]` |
| 1 | 1 | 0 | 1 | 2 | 1 < 2 | i++ | `[]` |
| 2 | 2 | 0 | 2 | 2 | = | push(2), i++, j++ | `[2]` |
| 3 | 3 | 1 | 2 | 2 | = | уже есть 2 → не push, i++, j++ | `[2]` |
| 4 | 4 | 2 | — | — | конец | — | `[2]` |

Ответ: `[2]`.

### Почему проверка на дубликат работает

Массивы отсортированы, значит одинаковые значения идут подряд. Если мы уже добавили число `x`, следующее такое же `x` будет сразу за ним. Проверки `result[result.length - 1] !== nums1[i]` достаточно.

### Сложность

O(n + m) по времени, O(1) дополнительной памяти (не считая результата).

## 5.4. Задача 15: ArrayIntersectionSorted

### Условие

То же самое, но **с учётом повторений**: если число встречается 3 раза в первом массиве и 2 раза во втором, в ответе оно должно быть 2 раза.

```text
Вход:  [1, 1, 2, 2] и [2, 2]
Выход: [2, 2]
```

### Идея

Отличается от задачи 12 только тем, что при равенстве мы **всегда** добавляем элемент, не проверяя дубликаты. Каждое совпадение — это ещё одно общее вхождение.

### Код

```typescript
export function arrayIntersectionSorted(nums1: number[], nums2: number[]): number[] {
    const result: number[] = [];
    let i = 0;
    let j = 0;

    while (i < nums1.length && j < nums2.length) {
        if (nums1[i] < nums2[j]) {
            i++;
        } else if (nums1[i] > nums2[j]) {
            j++;
        } else {
            result.push(nums1[i]);
            i++;
            j++;
        }
    }

    return result;
}
```

### Разбор

Вход: `[1, 1, 2, 3]` и `[1, 2, 2, 4]`.

| Шаг | i | j | nums1[i] | nums2[j] | Сравнение | Действие | Результат |
|-----|---|----|----------|----------|-----------|----------|-----------|
| 0 | 0 | 0 | 1 | 1 | = | push(1), i=1, j=1 | `[1]` |
| 1 | 1 | 1 | 1 | 2 | < | i=2 | `[1]` |
| 2 | 2 | 1 | 2 | 2 | = | push(2), i=3, j=2 | `[1, 2]` |
| 3 | 3 | 2 | 3 | 2 | > | j=3 | `[1, 2]` |
| 4 | 3 | 3 | 3 | 4 | < | i=4 | `[1, 2]` |
| 5 | 4 | 3 | — | — | конец | — | `[1, 2]` |

Ответ: `[1, 2]`.

### Почему это «минимум из количеств»

Каждое совпадение «расходует» по одному вхождению из каждого массива. Поэтому число повторений в ответе равно `min(count1, count2)`.

### Сложность

O(n + m) по времени, O(1) дополнительной памяти.

## 5.5. Задача 14: FindDifference

### Условие

Даны два отсортированных массива. Найти числа, которые есть в первом, но отсутствуют во втором. Ответ — без повторов.

```text
Вход:  [1, 2, 3, 4] и [2, 4, 6]
Выход: [1, 3]
```

### Идея

Сравниваем текущие элементы.

- `nums1[i] < nums2[j]` → элемента `nums1[i]` нет во втором массиве (все оставшиеся элементы `nums2` ещё больше). Добавляем его и двигаем `i`.
- `nums1[i] > nums2[j]` → во втором массиве есть числа меньше, которые надо «догнать». Двигаем `j`.
- Равны → число есть в обоих, пропускаем все его повторы в обоих массивах.

### Код

```typescript
export function findDifference(nums1: number[], nums2: number[]): number[] {
    const result: number[] = [];
    let i = 0;
    let j = 0;

    while (i < nums1.length) {
        if (j >= nums2.length || nums1[i] < nums2[j]) {
            if (result.length === 0 || result[result.length - 1] !== nums1[i]) {
                result.push(nums1[i]);
            }
            i++;
        } else if (nums1[i] > nums2[j]) {
            j++;
        } else {
            const val = nums1[i];
            while (i < nums1.length && nums1[i] === val) i++;
            while (j < nums2.length && nums2[j] === val) j++;
        }
    }

    return result;
}
```

### Разбор

Вход: `[1, 2, 3, 4]` и `[2, 4, 6]`.

| Шаг | i | j | nums1[i] | nums2[j] | Сравнение | Действие | Результат |
|-----|---|----|----------|----------|-----------|----------|-----------|
| 0 | 0 | 0 | 1 | 2 | 1 < 2 | push(1), i=1 | `[1]` |
| 1 | 1 | 0 | 2 | 2 | = | пропустить 2 в обоих, i=2, j=1 | `[1]` |
| 2 | 2 | 1 | 3 | 4 | 3 < 4 | push(3), i=3 | `[1, 3]` |
| 3 | 3 | 1 | 4 | 4 | = | пропустить 4, i=4, j=2 | `[1, 3]` |
| 4 | 4 | 2 | — | 6 | i закончился | конец | `[1, 3]` |

Ответ: `[1, 3]`.

### Почему условие `j >= nums2.length` стоит первым

Если второй массив закончился, а в первом ещё есть элементы, то все они отсутствуют во втором. Нужно продолжать добавлять их. Условие `j >= nums2.length || ...` как раз это обрабатывает.

Без него обращение к `nums2[j]` при `j === nums2.length` даст `undefined`, и сравнение будет некорректным.

### Сложность

O(n + m) по времени, O(1) дополнительной памяти.

## 5.6. Задача 13: IsSubsequence

### Условие

Даны строки `s` и `t`. Проверить, можно ли получить `s`, удалив некоторые символы из `t`, не меняя порядок.

```text
s = "abc", t = "ahbgdc" → true
s = "axc", t = "ahbgdc" → false
```

### Идея

Идём указателем `si` по `s`, а `ti` — по `t`. Ищем очередной символ `s[si]` в `t`.

- Если символы совпали — нашли, двигаем `si`.
- `ti` двигается **всегда**, потому что мы просматриваем `t` слева направо.
- Если `si` дошёл до конца `s`, значит все символы найдены по порядку.

### Код

```typescript
export function isSubsequence(s: string, t: string): boolean {
    let si = 0;
    let ti = 0;

    while (si < s.length && ti < t.length) {
        if (s[si] === t[ti]) {
            si++;
        }
        ti++;
    }

    return si === s.length;
}
```

### Разбор

` s = "ace"`, `t = "abcde"`.

| Шаг | si | ti | s[si] | t[ti] | Совпали? | Действие |
|-----|----|----|-------|-------|----------|----------|
| 0 | 0 | 0 | a | a | да | si=1, ti=1 |
| 1 | 1 | 1 | c | b | нет | ti=2 |
| 2 | 1 | 2 | c | c | да | si=2, ti=3 |
| 3 | 2 | 3 | e | d | нет | ti=4 |
| 4 | 2 | 4 | e | e | да | si=3, ti=5 |

`si === s.length` → `true`.

### Почему `ti++` вне `if`

Мы обязаны просмотреть каждый символ `t` хотя бы раз. Если символ не совпал, мы не можем «перепрыгнуть» его и искать дальше, не сдвинув `ti`. Поэтому `ti` увеличивается на каждой итерации.

`si` увеличивается только при совпадении — мы ищем символы `s` по порядку.

### Граничные случаи

| s | t | Ответ | Почему |
|---|---|-------|--------|
| `""` | `"abc"` | `true` | пустая строка — подпоследовательность любой |
| `"abc"` | `""` | `false` | нечего искать |
| `"abc"` | `"abc"` | `true` | полное совпадение |
| `"aec"` | `"abcde"` | `false` | порядок нарушен |

### Сложность

O(len(t)) по времени, O(1) дополнительной памяти.

## 5.7. Общая схема

Все пять задач используют один скелет:

```typescript
let i = 0;
let j = 0;

while (i < a.length && j < b.length) {
    if (a[i] < b[j]) {
        // элемент a[i] обработан
        i++;
    } else if (a[i] > b[j]) {
        // элемент b[j] обработан
        j++;
    } else {
        // совпадение
        // обработать
        i++;
        j++;
    }
}
```

Различия только в том, что делать при сравнении и что делать с остатками.

| Задача | `<` | `>` | `=` | Остатки |
|--------|-----|-----|-----|---------|
| Merge | взять `a[i]` | взять `b[j]` | взять любой | дописать оба |
| Intersection (уникальные) | i++ | j++ | добавить, если новый | не нужны |
| Intersection (с повторами) | i++ | j++ | добавить | не нужны |
| Difference | добавить `a[i]`, если новый | j++ | пропустить повторы | первый массив |
| Subsequence | — | — | si++ | ti++ всегда |

## 5.8. Типичные ошибки

### Ошибка 1. Забыть остаток при слиянии

```typescript
while (i < n && j < m) { ... }
return result; // потеряли хвост
```

После основного цикла обязательно допишите остатки обоих массивов.

### Ошибка 2. Выход за границы

```typescript
while (i < a.length && j < b.length) {
    if (a[i] < b[j]) { ... }
}
```

Условие `&&` обязательно. Если написать `||`, один из индексов выйдет за границу.

### Ошибка 3. Двигать оба указателя при `=` в difference

Если при равенстве просто сделать `i++` и `j++`, можно получить дубликаты в результате. Нужно пропустить **все** повторы числа в обоих массивах (или проверять последний добавленный элемент).

### Ошибка 4. Забыть про пустой массив

Если один массив пуст:
- merge должен вернуть второй;
- intersection — пустой массив;
- difference — первый массив (если второй пуст).

Проверьте, что циклы и условия это обрабатывают.

### Ошибка 5. Считать, что массивы отсортированы, когда это не так

Все задачи главы требуют отсортированности. Если условие не гарантирует её, сначала нужно отсортировать (если можно) или использовать другой подход.

### Ошибка 6. В subsequence двигать `si` без совпадения

```typescript
// Неправильно
if (s[si] === t[ti]) {
    si++;
}
si++; // всегда
```

Так вы пропустите символы `s`. `si` двигается только при совпадении.

### Ошибка 7. Неверный ответ в subsequence

Проверять нужно `si === s.length`, а не `ti === t.length`. Мы хотим узнать, найден ли **весь** `s`.

## Что запомнить из главы

1. Два массива — два указателя, по одному на каждый.
2. Двигается тот указатель, чей элемент «меньше» (или уже обработан).
3. При равенстве обрабатываем совпадение и двигаем оба.
4. После основного цикла не забываем остатки.
5. Условие цикла — `&&`, иначе выход за границы.
6. Все задачи главы опираются на отсортированность.
