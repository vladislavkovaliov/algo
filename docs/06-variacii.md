# Глава 6. Вариации: когда базовых шаблонов мало

В предыдущих главах мы разобрали три базовых семейства. В реальных задачах они часто комбинируются или слегка меняются. Эта глава — про такие вариации.

## 6.1. Задача 6: ThreeSumSorted (фиксируем один элемент)

### Условие

Дан отсортированный массив (в этой задаче — уникальные числа) и `target`. Найти все уникальные тройки, сумма которых равна `target`.

```text
Вход:  [1, 2, 3, 4, 5, 6], target = 9
Выход: [[1, 2, 6], [1, 3, 5], [2, 3, 4]]
```

### Идея: свести тройку к паре

Три указателя — это сложно. Но мы умеем решать задачу про **два** числа. Значит, зафиксируем первое число тройки и сведём задачу к поиску пары.

```text
для каждого i:
    найти пару (left, right) в nums[i+1 .. n-1],
    такую что nums[left] + nums[right] = target - nums[i]
```

Это классический приём **«сведение к известной задаче»**.

### Код

```typescript
export function threeSumSorted(nums: number[], target: number): number[][] {
    const triplets: number[][] = [];

    for (let i = 0; i < nums.length - 2; i++) {
        if (i > 0 && nums[i] === nums[i - 1]) continue;

        let left = i + 1;
        let right = nums.length - 1;

        while (left < right) {
            const sum = nums[i] + nums[left] + nums[right];

            if (sum === target) {
                triplets.push([nums[i], nums[left], nums[right]]);

                while (left < right && nums[left] === nums[left + 1]) left++;
                while (left < right && nums[right] === nums[right - 1]) right--;

                left++;
                right--;
            } else if (sum < target) {
                left++;
            } else {
                right--;
            }
        }
    }

    return triplets;
}
```

### Разбор

Вход: `[1, 2, 3, 4, 5, 6]`, `target = 9`.

**i = 0 (nums[i] = 1).** Нужна пара с суммой `8`.

| left | right | Сумма | Сравнение | Действие |
|------|-------|-------|-----------|----------|
| 1 | 5 | 1+2+6=9 | = | добавить `[1,2,6]`, left=2, right=4 |
| 2 | 4 | 1+3+5=9 | = | добавить `[1,3,5]`, left=3, right=3 |
| 3 | 3 | — | left < right ложно | конец i=0 |

**i = 1 (nums[i] = 2).** Нужна пара с суммой `7`.

| left | right | Сумма | Сравнение | Действие |
|------|-------|-------|-----------|----------|
| 2 | 5 | 2+3+6=11 | > | right=4 |
| 2 | 4 | 2+3+5=10 | > | right=3 |
| 2 | 3 | 2+3+4=9 | = | добавить `[2,3,4]`, left=3, right=2 |

**i = 2 (nums[i] = 3).** Нужна пара с суммой `6`, но остались только `[4,5]` с суммой 9. Не подходит.

Ответ: `[[1,2,6], [1,3,5], [2,3,4]]`.

### Зачем пропуск дубликатов

Если в массиве есть одинаковые числа, один и тот же набор можно получить несколько раз.

```text
nums = [1, 2, 2, 3, 4, 4, 5, 6]
```

Зафиксировав первое `2`, можно получить `[2,2,5]`. Зафиксировав второе `2` — снова `[2,2,5]`. Это дубликат.

Три проверки решают проблему:

```typescript
if (i > 0 && nums[i] === nums[i - 1]) continue;
```

Пропускает повтор первого элемента.

```typescript
while (left < right && nums[left] === nums[left + 1]) left++;
while (left < right && nums[right] === nums[right - 1]) right--;
```

Пропускает повторы внутри пары после найденной тройки.

### Важно: границы `left < right` внутри `while`

Нельзя писать просто:

```typescript
while (nums[left] === nums[left + 1]) left++;
```

На последнем элементе `left + 1` выйдет за границу. Условие `left < right` защищает.

### Сложность

- Внешний цикл: O(n).
- Внутренний проход: O(n).
- Итого: O(n²).
- Память: O(1) дополнительной (не считая ответа).

### Почему не O(n³)

Наивный перебор трёх вложенных циклов — O(n³). Мы заменили два внутренних цикла на один проход двумя указателями — получили O(n²).

## 6.2. Задача 17: ValidPalindromeRemoval (ветвление)

### Условие

Дана строка. Можно удалить **не более одного** символа. Проверить, станет ли строка палиндромом.

```text
"aba"  → true  (ничего удалять не нужно)
"abca" → true  (удалить 'b' или 'c')
"abc"  → false
```

### Идея

Идём двумя указателями с краёв, как в обычном палиндроме. Пока символы совпадают — двигаемся.

При **первом** несовпадении у нас есть два варианта:

1. Удалить левый символ и проверить остаток `[left+1, right]`.
2. Удалить правый символ и проверить остаток `[left, right-1]`.

Если хотя бы один вариант даёт палиндром — ответ `true`. Если оба нет — `false`.

### Код

```typescript
function isPalindromeFrom(s: string, left: number, right: number): boolean {
    while (left < right) {
        if (s[left] !== s[right]) return false;
        left++;
        right--;
    }
    return true;
}

export function validPalindromeRemoval(s: string): boolean {
    let left = 0;
    let right = s.length - 1;

    while (left < right) {
        if (s[left] !== s[right]) {
            return isPalindromeFrom(s, left + 1, right) ||
                   isPalindromeFrom(s, left, right - 1);
        }
        left++;
        right--;
    }

    return true;
}
```

### Разбор

Вход: `"abca"`.

| Шаг | left | right | s[left] | s[right] | Совпали? | Действие |
|-----|------|-------|---------|----------|----------|----------|
| 0 | 0 | 3 | a | a | да | left=1, right=2 |
| 1 | 1 | 2 | b | c | нет | ветвление |

Проверяем два варианта:

- Удалить левый (`b`): остаток `"aca"` → палиндром → `true`.
- Удалить правый (`c`): остаток `"aba"` → палиндром → `true`.

Результат: `true`.

### Почему достаточно одного ветвления

Мы можем удалить только **один** символ. Пока символы совпадают, удалять ничего не нужно. Первое несовпадение — единственное место, где нужно принимать решение. После удаления остаток обязан быть палиндромом **без дальнейших удалений**. Это и проверяет `isPalindromeFrom`.

### Сложность

- Время: O(n). Мы либо проходим строку один раз, либо делаем два прохода по остатку.
- Память: O(1).

### Типичная ошибка

Пытаться удалять символы рекурсивно в нескольких местах. Это уже не «не более одного удаления», а другая задача.

## 6.3. Задача 18: BackspaceStringCompare (сравнение с конца)

### Условие

Даны две строки с символами `#` (backspace). `#` удаляет предыдущий символ. Проверить, равны ли строки после применения всех backspace.

```text
"ab#c" → "ac"
"ad#c" → "ac"
Ответ: true
```

### Почему не применять backspace «в лоб»

Можно собрать строки в стеке или новом массиве:

```typescript
function applyBackspace(s: string): string {
    const stack: string[] = [];

    for (const ch of s) {
        if (ch === '#') {
            stack.pop();
        } else {
            stack.push(ch);
        }
    }

    return stack.join('');
}
```

Это O(n) по времени и O(n) по памяти. Работает, но можно обойтись O(1) памяти.

### Идея: идём с конца

Backspace удаляет символ **слева** от себя. Если идти с конца, мы встречаем `#` раньше, чем символ, который он удаляет. Значит, можем считать, сколько удалений «в ожидании».

```text
"ab#c"
    ↑
   идём с конца: c, затем #, затем b (его надо пропустить), затем a
```

### Код

```typescript
function nextValidIndex(str: string, index: number): number {
    let backspaces = 0;

    while (index >= 0) {
        if (str[index] === '#') {
            backspaces++;
        } else if (backspaces > 0) {
            backspaces--;
        } else {
            break;
        }
        index--;
    }

    return index;
}

export function backspaceStringCompare(s: string, t: string): boolean {
    let si = s.length - 1;
    let ti = t.length - 1;

    while (si >= 0 || ti >= 0) {
        si = nextValidIndex(s, si);
        ti = nextValidIndex(t, ti);

        const schar = si >= 0 ? s[si] : undefined;
        const tchar = ti >= 0 ? t[ti] : undefined;

        if (schar !== tchar) return false;

        si--;
        ti--;
    }

    return true;
}
```

### Как работает `nextValidIndex`

Функция возвращает индекс ближайшего слева символа, который **не удалён**.

- Если видит `#`, увеличивает счётчик `backspaces`.
- Если видит обычный символ и `backspaces > 0`, «тратит» одно удаление и идёт дальше.
- Если видит обычный символ и удалений нет — это нужный символ, останавливается.

Если дошла до начала — возвращает `-1` (все символы удалены).

### Разбор

`s = "ab#c"`, `t = "ad#c"`.

| Шаг | si | ti | nextValid(s, si) | nextValid(t, ti) | Символы | Равны? |
|-----|----|----|------------------|------------------|---------|--------|
| 0 | 3 | 3 | 3 (`c`) | 3 (`c`) | c, c | да |
| 1 | 2 | 2 | 0 (`a`) | 0 (`a`) | a, a | да |
| 2 | -1 | -1 | -1 | -1 | — | конец |

Ответ: `true`.

Поясним переход на шаге 1 для `s`:

```text
si = 2
s[2] = '#' → backspaces = 1, index = 1
s[1] = 'b' → backspaces > 0 → backspaces = 0, index = 0
s[0] = 'a' → backspaces = 0 → break, вернуть 0
```

Символ `b` удалён, остаётся `a`.

### Почему `while (si >= 0 || ti >= 0)`, а не `&&`

Строки могут иметь разную длину после обработки. Нужно продолжать, пока **хотя бы одна** строка не закончилась. Если одна закончилась, а другая нет, `nextValid` вернёт `-1` для первой, и сравнение с реальным символом второй даст `false`.

Если использовать `&&`, можно пропустить лишние символы в более длинной строке и ошибочно вернуть `true`.

### Сложность

- Время: O(n + m). Каждый символ просматривается один раз.
- Память: O(1).

## 6.4. Задача 20: FindLongestPalindrome (расширение от центра)

### Условие

Дана строка. Найти длину самой длинной подстроки-палиндрома.

```text
"babad"  → 3  ("bab" или "aba")
"cbbd"   → 2  ("bb")
"racecar" → 7
```

### Идея

У палиндрома есть **центр**. Если мы угадаем центр и будем расширяться в обе стороны, пока символы совпадают, мы найдём палиндром с этим центром.

Центр бывает двух видов:

1. **Нечётный** — один символ в центре: `"aba"`, центр — `b`.
2. **Чётный** — между двумя символами: `"abba"`, центр — между `b` и `b`.

Поэтому для каждой позиции `i` проверяем два центра:

- `(i, i)` — нечётный;
- `(i, i + 1)` — чётный.

### Код

```typescript
function expandFromCenter(s: string, left: number, right: number): number {
    while (left >= 0 && right < s.length && s[left] === s[right]) {
        left--;
        right++;
    }
    return right - left - 1;
}

export function findLongestPalindrome(s: string): number {
    if (s.length === 0) return 0;

    let maxLen = 1;

    for (let i = 0; i < s.length; i++) {
        const len1 = expandFromCenter(s, i, i);
        const len2 = expandFromCenter(s, i, i + 1);
        maxLen = Math.max(maxLen, len1, len2);
    }

    return maxLen;
}
```

### Почему `right - left - 1`

После цикла указатели стоят **на один шаг за пределами** палиндрома: `left` уменьшился, `right` увеличился, и именно на этой паре символы не совпали (или вышли за границу).

Длина последнего совпавшего отрезка:

```text
right - left - 1
```

Пример: `"aba"`, центр `(1,1)`.

```text
left=1, right=1: 'a' == 'a' → left=0, right=2
left=0, right=2: 'a' == 'a' → left=-1, right=3
left=-1 → выход
длина = 3 - (-1) - 1 = 3
```

### Разбор `"babad"`

| i | Центр | expand(i, i) | expand(i, i+1) | maxLen |
|---|-------|--------------|----------------|--------|
| 0 | b | 1 (`b`) | 0 (`b` != `a`) | 1 |
| 1 | a | 3 (`bab`) | 0 (`a` != `b`) | 3 |
| 2 | b | 3 (`aba`) | 0 (`b` != `a`) | 3 |
| 3 | a | 1 (`a`) | 0 (`a` != `d`) | 3 |
| 4 | d | 1 (`d`) | 0 (выход за границу) | 3 |

Ответ: `3`.

### Почему это O(n²)

Для каждого из `n` центров мы можем расшириться до `n` символов. Итого O(n²).

Это не самый быстрый алгоритм (существует алгоритм Манакера за O(n)), но самый понятный и достаточный для большинства учебных задач.

### Сложность

- Время: O(n²).
- Память: O(1).

### Типичная ошибка

Проверять только нечётные центры. Тогда `"cbbd"` даст `1` вместо `2`, потому что палиндром `"bb"` имеет чётный центр.

## 6.5. Как выбирать между вариациями

| Ситуация | Приём |
|----------|-------|
| Нужно найти тройку/четвёрку | Зафиксировать часть, свести к паре |
| Можно удалить один символ | Ветвление в точке несовпадения |
| Нужно сравнить строки с удалениями | Идти с конца, считать отложенные удаления |
| Нужно найти палиндром-подстроку | Расширяться от центра |
| Нужно построить результат с конца | Два указателя + запись в конец |

## Что запомнить из главы

1. Сложную задачу можно свести к уже известной: тройка → фиксация + пара.
2. Ветвление допустимо, если вариантов мало (два).
3. Иногда выгодно идти с конца: backspace удаляет влево, поэтому с конца видно «будущее».
4. Палиндром-подстрока ищется расширением от центра; центры бывают чётные и нечётные.
5. Комбинируйте шаблоны, но сохраняйте смысл указателей.
