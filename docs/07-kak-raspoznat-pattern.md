# Глава 7. Как распознать нужный паттерн

На собеседовании или контрольной никто не скажет: «решите это методом двух указателей». Нужно самому понять это по условию. В этой главе — набор сигналов и дерево решений.

---

## 7.1. Пять вопросов перед решением

Задайте их в таком порядке.

### 1. Сколько последовательностей на входе?

- Одна (массив или строка) → семейства A, B или D.
- Две → семейство C (по указателю на каждую).

### 2. Есть ли сортировка?

- Да, отсортировано → можно использовать монотонность, семейство B или C.
- Нет → либо сортировать (если можно), либо хеш-таблица, либо другой подход.

### 3. Что нужно сделать?

- Удалить / отфильтровать / сдвинуть → A (быстрый и медленный).
- Найти пару / границу / развернуть → B (с двух сторон).
- Слить / сравнить две последовательности → C.
- Найти палиндром-подстроку → D (от центра).
- Найти тройку/четвёрку → фиксация + B.

### 4. Можно ли менять входные данные?

- Да, in-place → можно писать в тот же массив (A).
- Нет → создаём результат (B, C).

### 5. Что вернуть: индексы, значения, длину или boolean?

- Индексы → нельзя менять порядок сортировкой.
- Длину полезной части → A, возвращаем `slow` или `slow + 1`.
- Значения → обычно результат собирается отдельно.
- Boolean → часто ранний выход (`return false` / `return true`).

## 7.2. Дерево решений

```text
Что на входе?
│
├── Одна последовательность (массив/строка)
│   │
│   ├── Нужно удалить/отфильтровать/сдвинуть?
│   │   └── ДА → Быстрый и медленный (A)
│   │       ├── можно выбросить элементы → перезапись
│   │       └── все элементы должны остаться → swap
│   │
│   ├── Нужно сравнить симметричные элементы / развернуть?
│   │   └── ДА → С двух сторон (B)
│   │
│   ├── Нужно найти пару/тройку по сумме?
│   │   ├── массив отсортирован → С двух сторон (B)
│   │   └── не отсортирован → сортировка + B или хеш-таблица
│   │
│   └── Нужно найти палиндром-подстроку?
│       └── ДА → Расширение от центра (D)
│
└── Две последовательности
    │
    ├── Обе отсортированы?
    │   └── ДА → По указателю на каждую (C)
    │
    └── Нужно проверить вхождение по порядку?
        └── ДА → По указателю на каждую (C)
```

## 7.3. Зелёные флаги

«Зелёный флаг» — слово или фраза в условии, которая намекает на паттерн.

| Фраза в условии | Вероятный паттерн |
|-----------------|-------------------|
| «отсортированный массив» | B или C |
| «in-place» | A или B (swap) |
| «удалить дубликаты» | A |
| «переместить нули» | A (swap) |
| «сохранить порядок» | A (перезапись) |
| «найти пару с суммой» | B (если отсортировано) |
| «найти тройку/четвёрку» | фиксация + B |
| «палиндром» | B (проверка) или D (поиск подстроки) |
| «развернуть» | B (swap) |
| «два массива» | C |
| «слить» | C |
| «пересечение» | C |
| «подпоследовательность» | C |
| «backspace» | B с конца |
| «удалить не более одного символа» | B с ветвлением |
| «максимальная площадь/контейнер» | B с жадным сдвигом |
| «квадраты отсортированного массива» | B + запись с конца |

### Осторожно: ложные друзья

- «Отсортированный» не всегда означает два указателя. Иногда достаточно бинарного поиска.
- «Палиндром» может означать проверку (B), поиск подстроки (D) или перестановку.
- «Два массива» не всегда указатели: если они не отсортированы и нужен поиск, может понадобиться хеш-таблица.
- «In-place» может означать и быстрый/медленный, и swap с краёв, и циклические перестановки.

## 7.5. Быстрые ассоциации

### «Удалить / оставить / сдвинуть» → A

```text
[1, 1, 2, 3, 3] → [1, 2, 3, ...]
[0, 1, 0, 3]    → [1, 3, 0, 0]
```

Два указателя, один читает, другой пишет.

### «Пара в отсортированном» → B

```text
[2, 7, 11, 15], target = 9 → [0, 1]
```

Края, сумма, сдвиг одного указателя.

### «Две последовательности» → C

```text
[1, 3, 5] + [2, 4, 6] → [1, 2, 3, 4, 5, 6]
```

По указателю на каждую.

### «Палиндром» → B или D

- Проверить всю строку → B.
- Найти самую длинную подстроку → D.

### «Тройка» → фиксация + B

```text
for i: найти пару в nums[i+1..] с суммой target - nums[i]
```

## 7.6. Если массив не отсортирован

Это отдельное решение. Варианты:

### Вариант 1. Отсортировать

```typescript
nums.sort((a, b) => a - b);
```

Стоимость O(n log n). После этого можно применять B.

**Когда можно:**
- задача просит значения, а не исходные индексы;
- порядок не важен.

**Когда нельзя:**
- нужно вернуть индексы исходного массива;
- порядок элементов имеет значение.

### Вариант 2. Хеш-таблица

Для поиска пары с суммой:

```typescript
function twoSumUnsorted(nums: number[], target: number): number[] {
    const seen = new Map<number, number>();

    for (let i = 0; i < nums.length; i++) {
        const need = target - nums[i];

        if (seen.has(need)) {
            return [seen.get(need)!, i];
        }

        seen.set(nums[i], i);
    }

    return [-1, -1];
}
```

O(n) по времени, O(n) по памяти.

### Вариант 3. Другой паттерн

Иногда задача вообще не про два указателя: сортировка, префиксные суммы, динамическое программирование, графы.

## 7.7. Как понять, что вы выбрали не тот паттерн

Признаки:

1. **Указатель должен иногда возвращаться назад.** Два указателя предполагают монотонное движение. Если правило требует «вернись и проверь ещё раз», паттерн не подходит.
2. **Не можете объяснить смысл указателя.** Если `left` — это «ну, какое-то число», вы двигаете наугад.
3. **Не можете сформулировать, что отбрасываете.** Без инварианта нет гарантии правильности.
4. **Решение требует проверить все пары, но вы пытаетесь пройти одним проходом.** Возможно, нужен другой подход.
5. **Массив не отсортирован, а вы используете монотонность.** Правило движения, скорее всего, неверно.

## 7.8. Упражнение: определите паттерн

Для каждой задачи назовите семейство и объясните одним предложением, что отбрасывается.

1. Дан отсортированный массив. Удалить все `0`, сохранив порядок остальных.
2. Дана строка. Проверить, является ли она палиндромом.
3. Даны два отсортированных массива. Найти все общие элементы без повторов.
4. Дан отсортированный массив. Найти максимальную сумму двух чисел, меньшую `K`.
5. Дан массив. Переместить все чётные числа в начало.
6. Дана строка. Найти длину самой длинной подстроки-палиндрома.
7. Дан отсортированный массив. Найти все тройки с суммой `0`.
8. Даны две строки. Проверить, является ли первая подпоследовательностью второй.
9. Дан массив символов. Развернуть его.
10. Дана строка. Проверить, можно ли удалить один символ, чтобы получить палиндром.

<details>
<summary>Ответы</summary>

1. A (перезапись). Отбрасываем нули.
2. B. Отбрасываем пары, которые не совпали.
3. C. Отбрасываем меньший элемент, он не может совпасть с текущим в другом массиве.
4. B. Отбрасываем край, который не может дать лучшую сумму.
5. A (swap). Отбрасываем уже расставленные чётные.
6. D. Расширяем каждый центр.
7. Фиксация + B. Для каждого `i` ищем пару с суммой `-nums[i]`.
8. C. Продвигаем указатель по второй строке, пока не найдём символ первой.
9. B. Меняем края.
10. B + ветвление. При несовпадении пробуем удалить левый или правый.

</details>

## 7.9. Шпаргалка на одну страницу

```text
ОДНА ПОСЛЕДОВАТЕЛЬНОСТЬ
  удалить/сдвинуть        → slow/fast, читатель/писатель
  пара в сортированном    → left/right, сумма
  палиндром целиком       → left/right, сравнение
  палиндром-подстрока     → центр + расширение
  развернуть              → left/right, swap

ДВЕ ПОСЛЕДОВАТЕЛЬНОСТИ
  обе сортированы         → i/j, меньший двигается
  вхождение по порядку    → i/j, ti всегда двигается

ТРОЙКА/ЧЕТВЁРКА
  фиксируй внешние, внутри → left/right

НЕ ОТСОРТИРОВАНО
  можно сортировать       → sort + два указателя
  нужны индексы           → хеш-таблица или сортировка пар (значение, индекс)
```
