# Глава 4. Указатели с двух сторон

Второе большое семейство. Два указателя стоят на краях и движутся **навстречу друг другу**, пока не встретятся.

---

## 4.1. Ментальная модель: два человека с концов шеренги

Представьте шеренгу людей. Один человек стоит слева, другой справа. Они смотрят на своих соседей и решают, кому из них сделать шаг к центру.

```text
left →                    ← right
[ 2,  7,  11,  15,  20,  25 ]
```

Область между указателями — это **ещё не проверенные кандидаты**. Каждый шаг один из указателей двигается, и область сужается.

Когда указатели встретились или пересеклись, проверять больше нечего.

### Почему это O(n)

Каждый указатель проходит не более `n` позиций. Вместе — не более `2n` шагов. Даже если на каждом шаге двигается только один, суммарное число шагов линейно.

## 4.2. Задача 3: IsPalindrome

### Условие

Дана строка. Проверить, читается ли она одинаково слева направо и справа налево.

```text
"racecar" → true
"hello"   → false
```

### Идея

Сравниваем первый символ с последним, второй с предпоследним и так далее. Если все пары совпали — палиндром. Если хотя бы одна не совпала — нет.

### Код

```typescript
export function isPalindrome(s: string): boolean {
    let left = 0;
    let right = s.length - 1;

    while (left < right) {
        if (s[left] !== s[right]) {
            return false;
        }
        left++;
        right--;
    }

    return true;
}
```

### Разбор

Вход: `"racecar"`.

| Шаг | left | right | s[left] | s[right] | Совпали? | Действие |
|-----|------|-------|---------|----------|----------|----------|
| 0 | 0 | 6 | r | r | да | left=1, right=5 |
| 1 | 1 | 5 | a | a | да | left=2, right=4 |
| 2 | 2 | 4 | c | c | да | left=3, right=3 |
| 3 | 3 | 3 | e | e | — | left < right ложно, выход |

Все пары совпали → `true`.

### Почему `left < right`, а не `left <= right`

Когда `left === right`, остался один средний символ. Он всегда равен сам себе, сравнивать его не нужно. Поэтому `<` достаточно.

Если написать `<=`, алгоритм тоже будет работать, просто сделает одну лишнюю итерацию. Но в задачах, где указатели меняются местами (реверс), `<=` может привести к лишнему обмену элемента с самим собой — не ошибка, но бессмысленная работа.

### Сложность

O(n) по времени, O(1) дополнительной памяти.

### Граничные случаи

| Вход | Ответ |
|------|-------|
| `""` | `true` (пустая строка — палиндром) |
| `"a"` | `true` |
| `"ab"` | `false` |
| `"aa"` | `true` |

## 4.3. Задача 16: ReverseString

### Условие

Дан массив символов. Развернуть его in-place.

```text
["h", "e", "l", "l", "o"] → ["o", "l", "l", "e", "h"]
```

### Идея

Меняем местами крайние элементы, затем следующие за ними, и так до центра.

### Код

```typescript
export function reverseString(s: string[]): string[] {
    let left = 0;
    let right = s.length - 1;

    while (left < right) {
        [s[left], s[right]] = [s[right], s[left]];
        left++;
        right--;
    }

    return s;
}
```

### Разбор

Вход: `["h", "e", "l", "l", "o"]`.

| Шаг | left | right | Обмен | Массив |
|-----|------|-------|-------|--------|
| 0 | 0 | 4 | h ↔ o | `["o", "e", "l", "l", "h"]` |
| 1 | 1 | 3 | e ↔ l | `["o", "l", "l", "e", "h"]` |
| 2 | 2 | 2 | left < right ложно | `["o", "l", "l", "e", "h"]` |

Ответ: `["o", "l", "l", "e", "h"]`.

### Сложность

O(n) по времени, O(1) дополнительной памяти.

### Связь с палиндромом

Реверс и проверка палиндрома — близнецы. В обоих случаях мы смотрим на симметричные пары. Только палиндром **сравнивает**, а реверс **меняет местами**.

## 4.4. Задача 2: TwoSumSorted

### Условие

Дан **отсортированный** массив и число `target`. Найти индексы двух чисел, сумма которых равна `target`.

```text
Вход:  [2, 7, 11, 15], target = 9
Выход: [0, 1]   (2 + 7 = 9)
```

### Идея

Ставим указатели на края. Смотрим на сумму.

- Сумма **меньше** `target` → нужно больше. Двигаем `left` вправо (там числа больше).
- Сумма **больше** `target` → нужно меньше. Двигаем `right` влево (там числа меньше).
- Сумма равна → ответ найден.

### Код

```typescript
export function twoSumSorted(numbers: number[], target: number): number[] {
    let left = 0;
    let right = numbers.length - 1;

    while (left < right) {
        const sum = numbers[left] + numbers[right];

        if (sum === target) {
            return [left, right];
        } else if (sum < target) {
            left++;
        } else {
            right--;
        }
    }

    return [-1, -1];
}
```

### Разбор

Вход: `[2, 7, 11, 15]`, `target = 9`.

| Шаг | left | right | nums[left] | nums[right] | Сумма | Сравнение | Действие |
|-----|------|-------|------------|-------------|-------|-----------|----------|
| 0 | 0 | 3 | 2 | 15 | 17 | > 9 | right-- |
| 1 | 0 | 2 | 2 | 11 | 13 | > 9 | right-- |
| 2 | 0 | 1 | 2 | 7 | 9 | = 9 | ответ `[0, 1]` |

### Почему правило движения не пропускает ответ

Это ключевой момент. Разберём для случая `sum > target`.

Пусть сейчас указатели стоят на `left` и `right`, и `nums[left] + nums[right] > target`.

Для **этого** `left` и **любого** `right' <= right`:

```text
nums[left] + nums[right'] <= nums[left] + nums[right] > target
```

Потому что массив отсортирован: чем левее `right'`, тем меньше число.

Значит, с текущим `left` ни один `right'` не даст `target`. Можно смело двигать `right` влево — мы ничего не теряем.

Аналогично для `sum < target`: с текущим `right` ни один `left' >= left` не даст `target`, потому что числа только растут. Двигаем `left`.

Это и есть **монотонность**, на которой держится метод.

### Почему нужен отсортированный массив

Если массив не отсортирован, из `sum > target` нельзя сделать вывод, что все числа левее меньше. Справа может стоять маленькое число, слева — большое. Правило ломается.

### Сложность

O(n) по времени (каждый указатель проходит массив один раз), O(1) дополнительной памяти.

### Сравнение с перебором

| Подход | Время | Память |
|--------|-------|--------|
| Два вложенных цикла | O(n²) | O(1) |
| Хеш-таблица | O(n) | O(n) |
| Два указателя (отсортировано) | O(n) | O(1) |

Два указателя выигрывают по памяти, но требуют отсортированности.

## 4.5. Задача 4: TwoSumLessThanK

### Условие

Дан отсортированный массив и число `k`. Найти **максимальную** сумму двух различных элементов, которая **строго меньше** `k`. Если такой пары нет — вернуть `-1`.

```text
Вход:  [2, 3, 4, 5], k = 10
Выход: 9   (4 + 5)
```

### Идея

Почти как TwoSumSorted, но вместо точного равенства мы ищем лучшую допустимую сумму.

- Если `sum < k` — пара допустима, запоминаем максимум и двигаем `left`, чтобы попробовать увеличить сумму.
- Если `sum >= k` — пара слишком большая, двигаем `right`, чтобы уменьшить.

### Код

```typescript
export function twoSumLessThanK(nums: number[], k: number): number {
    let left = 0;
    let right = nums.length - 1;
    let best = -1;

    while (left < right) {
        const sum = nums[left] + nums[right];

        if (sum < k) {
            best = Math.max(best, sum);
            left++;
        } else {
            right--;
        }
    }

    return best;
}
```

### Разбор

Вход: `[2, 3, 4, 5]`, `k = 10`.

| Шаг | left | right | Сумма | < 10? | best | Действие |
|-----|------|-------|-------|-------|------|----------|
| 0 | 0 | 3 | 7 | да | 7 | left++ |
| 1 | 1 | 3 | 8 | да | 8 | left++ |
| 2 | 2 | 3 | 9 | да | 9 | left++ |
| 3 | 3 | 3 | — | — | 9 | left < right ложно |

Ответ: `9`.

### Почему двигаем `left`, когда сумма подходит

Нам нужна **максимальная** сумма. При фиксированном `right` увеличение `left` увеличивает сумму. Значит, текущая пара — не последний шанс, можно попробовать больше.

### Почему двигаем `right`, когда сумма слишком большая

При фиксированном `right` и текущем `left` все `left' >= left` дают сумму не меньше текущей, то есть тоже `>= k`. Значит, с этим `right` допустимой пары нет. Двигаем `right`, чтобы уменьшить сумму.

### Сложность

O(n) по времени, O(1) дополнительной памяти.

## 4.6. Задача 5: ContainerWithMostWater

### Условие

Дан массив высот. Каждое число — высота вертикальной линии, стоящей в этой позиции. Нужно выбрать две линии, которые вместе с осью X образуют контейнер максимальной площади.

```text
height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
```

Площадь между линиями `i` и `j`:

```text
area = min(height[i], height[j]) × (j - i)
```

Почему `min`? Потому что вода нальётся только до уровня более низкой стенки.

### Идея

Ставим указатели на края. Считаем площадь. Затем двигаем указатель, который стоит на **более низкой** линии.

### Код

```typescript
export function containerWithMostWater(height: number[]): number {
    let left = 0;
    let right = height.length - 1;
    let maxArea = 0;

    while (left < right) {
        const area = Math.min(height[left], height[right]) * (right - left);
        maxArea = Math.max(maxArea, area);

        if (height[left] < height[right]) {
            left++;
        } else {
            right--;
        }
    }

    return maxArea;
}
```

### Разбор

Вход: `[1, 8, 6, 2, 5, 4, 8, 3, 7]`.

| Шаг | left | right | Высоты | Расстояние | Площадь | maxArea | Движение |
|-----|------|-------|--------|------------|---------|---------|----------|
| 0 | 0 | 8 | 1, 7 | 8 | 8 | 8 | left++ (1 < 7) |
| 1 | 1 | 8 | 8, 7 | 7 | 49 | 49 | right-- (7 < 8) |
| 2 | 1 | 7 | 8, 3 | 6 | 18 | 49 | right-- |
| 3 | 1 | 6 | 8, 8 | 5 | 40 | 49 | right-- (равны) |
| 4 | 1 | 5 | 8, 4 | 4 | 16 | 49 | right-- |
| 5 | 1 | 4 | 8, 5 | 3 | 15 | 49 | right-- |
| 6 | 1 | 3 | 8, 2 | 2 | 4 | 49 | right-- |
| 7 | 1 | 2 | 8, 6 | 1 | 6 | 49 | right-- |
| 8 | 1 | 1 | — | — | — | 49 | конец |

Ответ: `49`.

### Почему двигать более низкую линию безопасно

Это самый неочевидный момент. Разберём.

Пусть `height[left] < height[right]`. Текущая площадь ограничена высотой `height[left]`.

Если мы **оставим** `left` на месте и будем двигать `right` влево:

- расстояние `right - left` только уменьшится;
- высота контейнера не может стать больше `height[left]`, потому что `left` — более низкая стенка.

Значит, ни одна пара с текущим `left` и `right' < right` не даст площадь больше текущей. Текущий `left` **исчерпан**. Его можно двигать.

Если же мы двинем `left`, у нас появится шанс найти более высокую левую стенку и увеличить площадь.

Формально:

```text
Для всех right' < right:
min(height[left], height[right']) × (right' - left)
≤ height[left] × (right' - left)
< height[left] × (right - left)
= текущая площадь
```

То есть текущая площадь строго больше всех вариантов с тем же `left`. Отбрасываем их без потерь.

### Почему при равенстве можно двигать любой

Если `height[left] === height[right]`, обе стенки одинаково низкие. Движение любой из них не может ухудшить «потолок» по высоте, а расстояние уменьшится. В коде мы двигаем `right`. Это допустимо.

### Сложность

O(n) по времени, O(1) дополнительной памяти.

### Типичная ошибка

Двигать **более высокую** линию, потому что «она мешает». Нет: высокая линия не ограничивает площадь, ограничивает низкая. Двигать нужно именно низкую.

## 4.7. Задача 19: SquaresOfSortedArray

### Условие

Дан отсортированный по возрастанию массив, в котором могут быть отрицательные числа. Вернуть массив квадратов, тоже отсортированный по возрастанию.

```text
Вход:  [-4, -1, 0, 3, 10]
Выход: [0, 1, 9, 16, 100]
```

### Почему нельзя просто возвести в квадрат

Квадраты отрицательных чисел «переворачивают» порядок:

```text
[-4, -1, 0, 3, 10]
квадраты: [16, 1, 0, 9, 100]  — не отсортировано
```

### Идея

Самое большое число в массиве квадратов — это либо квадрат самого левого (самого отрицательного) числа, либо квадрат самого правого (самого положительного).

Значит, можно сравнивать квадраты крайних элементов и записывать больший **в конец результата**, двигая соответствующий указатель.

### Код

```typescript
export function squaresOfSortedArray(nums: number[]): number[] {
    const result: number[] = new Array(nums.length);
    let left = 0;
    let right = nums.length - 1;

    for (let pos = nums.length - 1; pos >= 0; pos--) {
        const leftSquare = nums[left] * nums[left];
        const rightSquare = nums[right] * nums[right];

        if (leftSquare > rightSquare) {
            result[pos] = leftSquare;
            left++;
        } else {
            result[pos] = rightSquare;
            right--;
        }
    }

    return result;
}
```

### Разбор

Вход: `[-4, -1, 0, 3, 10]`.

| pos | left | right | left² | right² | Выбор | Результат |
|-----|------|-------|-------|--------|-------|-----------|
| 4 | 0 | 4 | 16 | 100 | 100 | `[ , , , , 100]` |
| 3 | 0 | 3 | 16 | 9 | 16 | `[ , , , 16, 100]` |
| 2 | 1 | 3 | 1 | 9 | 9 | `[ , , 9, 16, 100]` |
| 1 | 1 | 2 | 1 | 0 | 1 | `[ , 1, 9, 16, 100]` |
| 0 | 2 | 2 | 0 | 0 | 0 | `[0, 1, 9, 16, 100]` |

Ответ: `[0, 1, 9, 16, 100]`.

### Почему заполняем с конца

Потому что мы умеем быстро находить **самый большой** квадрат (он всегда на одном из краёв), а не самый маленький. Записывая большие элементы в конец, мы строим результат от большего к меньшему.

### Сложность

O(n) по времени, O(n) дополнительной памяти (создаём результат).

### Альтернатива

Можно возвести все числа в квадрат и отсортировать: O(n log n). Два указателя быстрее, потому что используем уже существующую отсортированность.

## 4.8. Как не ошибиться с условием цикла

| Задача | Условие | Почему |
|--------|---------|--------|
| Палиндром | `left < right` | средний элемент не с чем сравнивать |
| Реверс | `left < right` | средний элемент не с чем менять |
| TwoSumSorted | `left < right` | нужны два **разных** индекса |
| TwoSumLessThanK | `left < right` | нужны два различных элемента |
| Container | `left < right` | нужны две разные линии |
| Squares | цикл по `pos`, не по указателям | указатели двигаются внутри |

Если написать `left <= right` в TwoSumSorted, можно случайно взять один и тот же элемент дважды (если `left === right`). Поэтому для пар всегда `<`.

## 4.9. Типичные ошибки

### Ошибка 1. Двигать не тот указатель

В TwoSumSorted при `sum < target` нужно двигать `left` (увеличивать), а не `right`. Легко перепутать, если думать «сумма маленькая — надо уменьшить». Наоборот: маленькая сумма → нужно больше.

### Ошибка 2. Двигать оба указателя сразу

```typescript
// Неправильно
if (sum < target) {
    left++;
    right--;
}
```

Так вы пропускаете пары. На каждом шаге двигается **ровно один** указатель (кроме случая, когда ответ уже найден).

### Ошибка 3. Проверять сумму после сдвига

```typescript
// Неправильно
left++;
const sum = nums[left] + nums[right];
```

Вы сравниваете уже другую пару. Сначала считаем сумму для текущих указателей, потом принимаем решение, потом двигаем.

### Ошибка 4. Забыть `right = n - 1`

```typescript
let right = nums.length; // ошибка: выход за границы
```

Правильно: `nums.length - 1`.

### Ошибка 5. В контейнере двигать высокую стенку

Площадь ограничена низкой стенкой. Двигать высокую бессмысленно: она не мешает, а расстояние только уменьшится.

### Ошибка 6. Считать площадь как `height[left] * height[right]`

Нет. Площадь — `min(height[left], height[right]) * (right - left)`. Высота воды ограничена более низкой стенкой, а ширина — расстоянием.

### Ошибка 7. В squares забыть, что результат заполняется с конца

Если писать `result[i]` слева направо, порядок будет неправильным. Индекс `pos` идёт от `n - 1` к `0`.

## Что запомнить из главы

1. Указатели с краёв сужают область кандидатов.
2. Отсортированность даёт монотонность: можно безопасно отбрасывать край.
3. В паре задач двигаем ровно один указатель за шаг.
4. В контейнере двигаем **более низкую** стенку.
5. Для пар используем `left < right`.
6. Squares показывает, что указатели могут идти с краёв, а результат заполняться с конца.
