# Глава 3. Быстрый и медленный указатели

Это первое большое семейство. Здесь два указателя движутся **в одну сторону**, но делают разную работу.

---

## 3.1. Ментальная модель: читатель и писатель

Представьте конвейер.

- **Читатель** (`fast`) берёт каждый предмет и решает: нужен он или нет.
- **Писатель** (`slow`) кладёт нужные предметы в новую стопку.

Писатель никогда не обгоняет читателя. Если предмет не нужен, писатель стоит на месте, а читатель идёт дальше.

```text
nums:  [ 3,  1,  2,  4,  5,  6 ]
        ↑
      slow
        ↑
       fast

fast читает 3 — не нужен (нечётный) → fast идёт дальше
fast читает 1 — не нужен → fast идёт дальше
fast читает 2 — нужен → записываем на slow, slow идёт дальше
```

Второе название семейства — **read/write pointers** (указатели чтения и записи).

### Почему это работает

Мы не создаём новый массив. Мы пишем «полезные» элементы в начало того же массива. Всё, что находится после `slow`, — либо уже обработано, либо мусор, который нам больше не нужен.

**Инвариант:**

> После обработки очередного `fast` первые `slow` элементов массива — это ровно те элементы, которые нужно было сохранить, в исходном порядке.

## 3.2. Задача 1: RemoveDuplicates

### Условие

Дан массив, отсортированный по возрастанию. Удалить дубликаты **in-place**, чтобы каждое число встречалось один раз. Вернуть новую длину.

```text
Вход:  [1, 1, 2]
Выход: 2   (первые два элемента должны быть [1, 2])
```

### Почему отсортированность важна

Если массив отсортирован, все одинаковые числа стоят рядом. Значит, чтобы понять, является ли текущее число новым, достаточно сравнить его с **последним сохранённым**.

Если массив не отсортирован, одинаковые числа могут быть разбросаны, и этот приём не сработает.

### Идея

- `slow` — индекс последнего уникального элемента.
- `fast` — индекс текущего проверяемого элемента.

Если `nums[fast]` отличается от `nums[slow]`, значит встретилось новое число:

1. увеличиваем `slow`;
2. записываем `nums[fast]` на позицию `slow`.

Если равно — это дубликат, пропускаем.

### Код

```typescript
export function removeDuplicates(nums: number[]): number {
    if (nums.length === 0) return 0;

    let slow = 0;

    for (let fast = 1; fast < nums.length; fast++) {
        if (nums[fast] !== nums[slow]) {
            slow++;
            nums[slow] = nums[fast];
        }
    }

    return slow + 1;
}
```

### Пошаговый разбор

Вход: `[1, 1, 2]`.

Начало: `slow = 0`, `fast = 1`.

| Шаг | fast | nums[fast] | nums[slow] | Равны? | Действие | Массив |
|-----|------|------------|------------|--------|----------|--------|
| 1 | 1 | 1 | 1 | да | пропуск | `[1, 1, 2]` |
| 2 | 2 | 2 | 1 | нет | slow = 1; nums[1] = 2 | `[1, 2, 2]` |

Конец. `slow + 1 = 2`.

Первые два элемента: `[1, 2]`. Хвост `[2]` — мусор, его никто не проверяет.

### Разбор на массиве длиннее

Вход: `[0, 0, 1, 1, 1, 2, 2, 3, 3, 4]`.

| fast | nums[fast] | slow | nums[slow] | Действие | Массив (первые позиции) |
|------|------------|------|------------|----------|--------------------------|
| 1 | 0 | 0 | 0 | пропуск | `[0, 0, 1, 1, 1, 2, 2, 3, 3, 4]` |
| 2 | 1 | 0 | 0 | slow=1, nums[1]=1 | `[0, 1, 1, 1, 1, 2, 2, 3, 3, 4]` |
| 3 | 1 | 1 | 1 | пропуск | `[0, 1, 1, 1, 1, 2, 2, 3, 3, 4]` |
| 4 | 1 | 1 | 1 | пропуск | `[0, 1, 1, 1, 1, 2, 2, 3, 3, 4]` |
| 5 | 2 | 1 | 1 | slow=2, nums[2]=2 | `[0, 1, 2, 1, 1, 2, 2, 3, 3, 4]` |
| 6 | 2 | 2 | 2 | пропуск | `[0, 1, 2, 1, 1, 2, 2, 3, 3, 4]` |
| 7 | 3 | 2 | 2 | slow=3, nums[3]=3 | `[0, 1, 2, 3, 1, 2, 2, 3, 3, 4]` |
| 8 | 3 | 3 | 3 | пропуск | `[0, 1, 2, 3, 1, 2, 2, 3, 3, 4]` |
| 9 | 4 | 3 | 3 | slow=4, nums[4]=4 | `[0, 1, 2, 3, 4, 2, 2, 3, 3, 4]` |

Ответ: `5`. Первые пять элементов: `[0, 1, 2, 3, 4]`.

### Доказательство

Инвариант: перед началом итерации с индексом `fast` первые `slow + 1` элементов массива — уникальные элементы из уже просмотренной части `nums[0..fast-1]`, в исходном порядке.

- База: `fast = 1`, `slow = 0`, первый элемент уникален.
- Шаг:
  - если `nums[fast] === nums[slow]`, число уже есть, ничего не меняем;
  - если отличается, это новое число (массив отсортирован), увеличиваем `slow` и записываем его.
- Завершение: просмотрены все элементы, `slow + 1` — количество уникальных.

### Сложность

- Время: O(n) — один проход.
- Дополнительная память: O(1) — две переменные.

### Граничные случаи

| Вход | Ответ | Почему |
|------|-------|--------|
| `[]` | `0` | пустой массив |
| `[1]` | `1` | один элемент уже уникален |
| `[1, 1, 1]` | `1` | все одинаковые |
| `[1, 2, 3]` | `3` | дубликатов нет |

## 3.3. Общий шаблон фильтрации

Задача 1 — частный случай большого шаблона:

```typescript
function filterInPlace(nums: number[]): number {
    let slow = 0;

    for (let fast = 0; fast < nums.length; fast++) {
        if (/* условие: элемент нужно сохранить */) {
            nums[slow] = nums[fast];
            slow++;
        }
    }

    return slow;
}
```

Меняется только условие:

| Задача | Условие «сохранить» | Что вернуть |
|--------|---------------------|-------------|
| RemoveDuplicates | `nums[fast] !== nums[slow]` | `slow + 1` |
| RemoveElement | `nums[fast] !== val` | `slow` |
| MoveZeroes | `nums[fast] !== 0` | сам массив (swap) |
| SortArrayByParity | `nums[fast] % 2 === 0` | сам массив (swap) |

Обратите внимание: в одних задачах мы **перезаписываем** элемент, в других **меняем местами**. Это важное различие.

## 3.4. Перезапись или обмен местами?

### Перезапись (`nums[slow] = nums[fast]`)

Используется, когда «ненужные» элементы можно выбросить.

```typescript
nums[slow] = nums[fast];
slow++;
```

- Порядок сохраняемых элементов сохраняется.
- Старые значения остаются в хвосте как мусор.
- Подходит для удаления.

### Обмен (`[nums[slow], nums[fast]] = [nums[fast], nums[slow]]`)

Используется, когда **все** элементы должны остаться в массиве, просто в другом порядке.

```typescript
[nums[slow], nums[fast]] = [nums[fast], nums[slow]];
slow++;
```

- Ничего не теряется.
- Порядок внутри групп может измениться.
- Подходит для перемещения нулей и разделения на группы.

### Сравнение

| Свойство | Перезапись | Обмен |
|----------|------------|-------|
| Теряются ли элементы | Да, «ненужные» | Нет |
| Сохраняется ли порядок полезных | Да | Да (для полезных) |
| Сохраняется ли порядок остальных | Не важно | Может нарушиться |
| Типичные задачи | удаление, дедупликация | move zeroes, parity |

## 3.5. Задача 8: RemoveElement

### Условие

Дан массив `nums` и число `val`. Удалить все вхождения `val` in-place, сохранив порядок остальных. Вернуть новую длину.

```text
Вход:  [3, 2, 2, 3], val = 3
Выход: 2   (первые два элемента — [2, 2])
```

### Идея

Тот же читатель/писатель, но условие другое: сохраняем всё, что **не равно** `val`.

### Код

```typescript
export function removeElement(nums: number[], val: number): number {
    let slow = 0;

    for (let fast = 0; fast < nums.length; fast++) {
        if (nums[fast] !== val) {
            nums[slow] = nums[fast];
            slow++;
        }
    }

    return slow;
}
```

### Разбор

Вход: `[3, 2, 2, 3]`, `val = 3`.

| fast | nums[fast] | ≠ 3? | Действие | Массив |
|------|------------|------|----------|--------|
| 0 | 3 | нет | пропуск | `[3, 2, 2, 3]` |
| 1 | 2 | да | nums[0] = 2, slow = 1 | `[2, 2, 2, 3]` |
| 2 | 2 | да | nums[1] = 2, slow = 2 | `[2, 2, 2, 3]` |
| 3 | 3 | нет | пропуск | `[2, 2, 2, 3]` |

Ответ: `2`. Первые два элемента: `[2, 2]`.

Обратите внимание: `nums[0]` был перезаписан, но это нормально — старое значение `3` нам не нужно.

### Почему порядок сохраняется

`fast` идёт слева направо. Каждый сохранённый элемент записывается в `slow`, который увеличивается только после записи. Значит, элементы попадают в начало в том же порядке, в котором встретились.

### Сложность

O(n) по времени, O(1) дополнительной памяти.

## 3.6. Задача 7: MoveZeroes

### Условие

Переместить все нули в конец массива, сохранив порядок ненулевых. Изменять in-place.

```text
Вход:  [0, 1, 0, 3, 12]
Выход: [1, 3, 12, 0, 0]
```

### Почему здесь нужен обмен, а не перезапись

Если просто перезаписать ненулевые в начало:

```text
[0, 1, 0, 3, 12] → [1, 3, 12, ?, ?]
```

что писать в хвост? Нули. Но откуда их взять? Можно после цикла заполнить хвост нулями — это тоже рабочий вариант. Однако обмен делает всё за один проход и не требует второго цикла.

### Код через обмен

```typescript
export function moveZeroes(nums: number[]): number[] {
    let slow = 0;

    for (let fast = 0; fast < nums.length; fast++) {
        if (nums[fast] !== 0) {
            [nums[slow], nums[fast]] = [nums[fast], nums[slow]];
            slow++;
        }
    }

    return nums;
}
```

### Разбор

Вход: `[0, 1, 0, 3, 12]`.

| fast | nums[fast] | Ненулевой? | Обмен | slow | Массив |
|------|------------|------------|-------|------|--------|
| 0 | 0 | нет | — | 0 | `[0, 1, 0, 3, 12]` |
| 1 | 1 | да | nums[0] ↔ nums[1] | 1 | `[1, 0, 0, 3, 12]` |
| 2 | 0 | нет | — | 1 | `[1, 0, 0, 3, 12]` |
| 3 | 3 | да | nums[1] ↔ nums[3] | 2 | `[1, 3, 0, 0, 12]` |
| 4 | 12 | да | nums[2] ↔ nums[4] | 3 | `[1, 3, 12, 0, 0]` |

Ответ: `[1, 3, 12, 0, 0]`.

### Почему порядок ненулевых сохраняется

`slow` — это позиция, куда попадёт следующий ненулевой. Все позиции до `slow` уже заняты ненулевыми в исходном порядке. Когда `fast` находит новый ненулевой, он меняется с элементом на `slow`. Если `slow` указывает на ноль — ноль уходит назад, ненулевой встаёт на своё место. Если `slow == fast` (например, нулей ещё не было), обмен ничего не меняет.

### Альтернатива через перезапись

```typescript
function moveZeroes2(nums: number[]): number[] {
    let slow = 0;

    for (let fast = 0; fast < nums.length; fast++) {
        if (nums[fast] !== 0) {
            nums[slow] = nums[fast];
            slow++;
        }
    }

    while (slow < nums.length) {
        nums[slow] = 0;
        slow++;
    }

    return nums;
}
```

Оба варианта корректны. Первый короче, второй иногда понятнее.

### Сложность

O(n) по времени, O(1) дополнительной памяти.

## 3.7. Задача 9: SortArrayByParity

### Условие

Переставить элементы так, чтобы сначала шли чётные, потом нечётные. Порядок внутри групп не важен. In-place.

```text
Вход:  [3, 1, 2, 4]
Выход: [2, 4, 3, 1]
```

### Идея

Условие «сохранить» — элемент чётный. Но, в отличие от удаления, нам нужно сохранить **все** элементы. Поэтому используем обмен.

### Код

```typescript
export function sortArrayByParity(nums: number[]): number[] {
    let slow = 0;

    for (let fast = 0; fast < nums.length; fast++) {
        if (nums[fast] % 2 === 0) {
            [nums[slow], nums[fast]] = [nums[fast], nums[slow]];
            slow++;
        }
    }

    return nums;
}
```

### Разбор

Вход: `[3, 1, 2, 4]`.

| fast | nums[fast] | Чётный? | Обмен | slow | Массив |
|------|------------|---------|-------|------|--------|
| 0 | 3 | нет | — | 0 | `[3, 1, 2, 4]` |
| 1 | 1 | нет | — | 0 | `[3, 1, 2, 4]` |
| 2 | 2 | да | nums[0] ↔ nums[2] | 1 | `[2, 1, 3, 4]` |
| 3 | 4 | да | nums[1] ↔ nums[3] | 2 | `[2, 4, 3, 1]` |

Ответ: `[2, 4, 3, 1]`.

### Почему нечётные оказались в конце

Каждый чётный элемент «перепрыгивает» на границу `slow`, а нечётный, стоявший там, уходит на место `fast`. Так нечётные постепенно вытесняются вправо.

### Важное замечание о порядке

В условии сказано «порядок внутри групп не важен». Но тесты могут ожидать конкретный массив. В этой задаче тест ожидает `[2, 4, 3, 1]`, а не, например, `[4, 2, 1, 3]`. Поэтому используйте именно этот алгоритм, если проходите тесты проекта.

Если бы требовался **устойчивый** порядок (чётные в исходном порядке, затем нечётные в исходном порядке), понадобился бы дополнительный массив или более сложная схема. Это уже не O(1) по памяти.

### Сложность

O(n) по времени, O(1) дополнительной памяти.

## 3.8. Задача 10: RemoveDuplicatesFromSortedArray2

### Условие

Отсортированный массив. Удалить дубликаты так, чтобы каждое число встречалось **не более двух раз**. Вернуть длину.

```text
Вход:  [1, 1, 1, 2, 2, 3]
Выход: 5   (первые пять элементов: [1, 1, 2, 2, 3])
```

### Идея

Обобщим задачу 1. Там мы разрешали **одно** вхождение и сравнивали с `nums[slow]`. Здесь разрешаем **два** вхождения, поэтому сравниваем с элементом, который стоит на **две позиции назад**: `nums[slow - 2]`.

Если текущее число равно `nums[slow - 2]`, значит это уже третье (или больше) вхождение — пропускаем. Если отличается — можно записывать.

### Код

```typescript
export function removeDuplicates2(nums: number[]): number {
    if (nums.length <= 2) return nums.length;

    let slow = 2;

    for (let fast = 2; fast < nums.length; fast++) {
        if (nums[fast] !== nums[slow - 2]) {
            nums[slow] = nums[fast];
            slow++;
        }
    }

    return slow;
}
```

### Почему `slow = 2` и `fast = 2`

Первые два элемента можно оставить как есть: даже если они одинаковые, это допустимо (не более двух). Поэтому оба указателя начинают с индекса 2.

### Разбор

Вход: `[1, 1, 1, 2, 2, 3]`.

Начало: `slow = 2`, `fast = 2`.

| fast | nums[fast] | slow | nums[slow-2] | Равны? | Действие | Массив |
|------|------------|------|--------------|--------|----------|--------|
| 2 | 1 | 2 | nums[0] = 1 | да | пропуск | `[1, 1, 1, 2, 2, 3]` |
| 3 | 2 | 2 | nums[0] = 1 | нет | nums[2] = 2, slow = 3 | `[1, 1, 2, 2, 2, 3]` |
| 4 | 2 | 3 | nums[1] = 1 | нет | nums[3] = 2, slow = 4 | `[1, 1, 2, 2, 2, 3]` |
| 5 | 3 | 4 | nums[2] = 2 | нет | nums[4] = 3, slow = 5 | `[1, 1, 2, 2, 3, 3]` |

Ответ: `5`. Первые пять элементов: `[1, 1, 2, 2, 3]`.

### Почему сравнение с `slow - 2` работает

К моменту обработки `fast` первые `slow` элементов уже содержат корректный результат: каждое число встречается не более двух раз.

- `nums[slow - 1]` — последнее записанное число.
- `nums[slow - 2]` — число, которое было записано два шага назад.

Если текущее число равно `nums[slow - 2]`, то среди последних записей уже есть два таких же числа (на позициях `slow - 2` и `slow - 1`), значит третье писать нельзя.

Если отличается — либо это новое число, либо предыдущее встречалось меньше двух раз.

### Обобщение на K повторов

Для «не более K раз»:

```typescript
function removeDuplicatesK(nums: number[], k: number): number {
    if (nums.length <= k) return nums.length;

    let slow = k;

    for (let fast = k; fast < nums.length; fast++) {
        if (nums[fast] !== nums[slow - k]) {
            nums[slow] = nums[fast];
            slow++;
        }
    }

    return slow;
}
```

При `k = 1` получим задачу 1 (с точностью до начальных индексов), при `k = 2` — задачу 10.

### Сложность

O(n) по времени, O(1) дополнительной памяти.

## 3.9. Типичные ошибки

### Ошибка 1. Увеличить `slow` до записи

```typescript
// Неправильно
slow++;
nums[slow] = nums[fast];
```

Вы «перепрыгиваете» через позицию и оставляете дырку. Правильно:

```typescript
nums[slow] = nums[fast];
slow++;
```

### Ошибка 2. Вернуть `slow` вместо `slow + 1`

В задаче 1 `slow` — **индекс** последнего уникального элемента. Количество элементов — `slow + 1`.

```typescript
// Для [1, 2, 3]: slow = 2, но длина = 3
return slow + 1;
```

В задаче 8 `slow` — это уже **количество** записанных элементов, потому что старт с нуля и запись идёт перед увеличением. Поэтому там `return slow`.

Всегда проверяйте, что именно хранит переменная: индекс или количество.

### Ошибка 3. Неверный старт

```typescript
// Задача 1
let slow = 0;
for (let fast = 0; fast < nums.length; fast++) { ... }
```

Если `fast` начинается с 0, то на первой итерации `nums[fast] === nums[slow]`, и всё работает, но лишняя итерация. Не ошибка, но шум. Главное — не начинать `slow` с 1, иначе первый элемент будет потерян.

### Ошибка 4. Перезапись вместо обмена

В MoveZeroes перезапись без заполнения хвоста нулями даст неправильный массив:

```typescript
// Неправильно: хвост остаётся старым
nums[slow] = nums[fast];
```

Нужен либо swap, либо второй цикл для нулей.

### Ошибка 5. Забыть про пустой массив

В задачах, где вы обращаетесь к `nums[0]` или `nums[slow - 2]`, пустой массив может дать ошибку. Проверяйте длину в начале.

### Ошибка 6. Дубликаты в неотсортированном массиве

`RemoveDuplicates` работает только потому, что равные элементы стоят рядом. Для неотсортированного массива нужно сначала отсортировать или использовать хеш-таблицу.

### Ошибка 7. Сравнение не с тем элементом

В задаче 10 сравнение с `nums[slow - 1]` (как в задаче 1) разрешит только одно вхождение, а не два. Сравнение с `nums[slow - 2]` — ключ к обобщению.

## 3.10. Как отлаживать этот паттерн

1. Нарисуйте массив и две стрелки.
2. На каждом шаге выписывайте: `fast`, `nums[fast]`, `slow`, `nums[slow]`, решение, массив после.
3. Проверьте, что `slow` никогда не больше `fast`.
4. Проверьте, что каждый элемент либо записан, либо осознанно пропущен.
5. В конце проверьте, что первые `slow` (или `slow + 1`) элементов — правильный ответ.

### Таблица для отладки

| fast | nums[fast] | slow | nums[slow] | Решение | Массив |

| | | | | | |

Заполняйте её от руки. Это быстрее, чем десять раз перезапускать тесты.

## 3.11. Практика

Решите самостоятельно, затем сверьтесь с разборами в папке задачи.

1. `Task1_RemoveDuplicates` — удалить дубликаты.
2. `Task8_RemoveElement` — удалить все вхождения `val`.
3. `Task7_MoveZeroes` — переместить нули в конец.
4. `Task9_SortArrayByParity` — чётные вперёд.
5. `Task10_RemoveDuplicatesFromSortedArray2` — не более двух повторов.

Дополнительно:

6. Дан массив. Оставить только положительные числа, сохранив порядок. Вернуть длину.
7. Дан массив. Переместить все чётные числа в конец, нечётные — в начало, порядок внутри групп не важен.
8. Дан отсортированный массив. Оставить не более трёх повторов каждого числа.

## Что запомнить из главы

1. `fast` читает всё, `slow` пишет нужное.
2. `slow` — граница полезной части; хвост — мусор.
3. Перезапись — когда можно выбрасывать; swap — когда все элементы должны остаться.
4. В задаче 1 возвращаем `slow + 1`, в задаче 8 — `slow`. Следите за смыслом переменной.
5. Для K повторов сравниваем с `nums[slow - K]`.
6. Инвариант: первые `slow` элементов — корректный ответ на уже просмотренной части.
