# Глава 1. Основы, без которых два указателя не работают

Эта глава — фундамент. Здесь нет ни одной задачи на два указателя. Мы разберёмся, что такое массив, индекс, цикл, функция, сложность и память.

Если вы уже уверенно пишете циклы и понимаете `nums[i]`, можете пробежать главу по диагонали и вернуться к ней, когда встретите незнакомое слово.

---

## 1.1. Что такое алгоритм

**Алгоритм** — это конечная последовательность понятных шагов, которая превращает входные данные в результат.

Пример из жизни: рецепт бутерброда.

1. Взять два куска хлеба.
2. Намазать один маслом.
3. Положить сыр.
4. Накрыть вторым куском.

У алгоритма есть три свойства:

- **Вход** — что дано.
- **Выход** — что нужно получить.
- **Конечность** — алгоритм обязан когда-то закончиться.

В программировании алгоритм записывают в виде функции.

```typescript
function add(a: number, b: number): number {
    return a + b;
}
```

Читается так: «функция `add` принимает два числа `a` и `b`, возвращает число; результат — `a + b`».

- `function` — объявление функции;
- `add` — имя;
- `(a: number, b: number)` — входные параметры и их типы;
- `: number` после скобок — тип результата;
- `return` — что именно вернуть.

Вызвать функцию:

```typescript
const result = add(2, 3); // result = 5
```

## 1.2. Массив и индекс

**Массив** — это упорядоченный набор элементов, расположенных подряд.

```text
значения:  10   20   30   40   50
индексы:    0    1    2    3    4
```

Индекс — это **номер элемента**. В программировании нумерация почти всегда начинается с нуля.

Почему с нуля? Удобная модель: индекс — это **смещение от начала**. Первый элемент стоит на расстоянии 0 шагов от начала, второй — на расстоянии 1 шага, и так далее.

### Доступ по индексу

```typescript
const nums = [10, 20, 30, 40, 50];

console.log(nums[0]);  // 10
console.log(nums[2]);  // 30
console.log(nums[4]);  // 50
```

Обращение `nums[i]` — это **одна операция**, независимо от длины массива. Компьютер знает, где начинается массив, и прибавляет к адресу `i` элементов. Поэтому говорят: доступ по индексу стоит **O(1)**.

### Длина массива

```typescript
const n = nums.length; // 5
```

Важно: **последний индекс равен `n - 1`**, а не `n`.

```text
nums = [10, 20, 30, 40, 50]
n = 5
последний индекс = 4
```

Если обратиться к `nums[5]`, элемента нет. В TypeScript получится `undefined`, а во многих других языках — ошибка.

### Выход за границы

Классическая ошибка новичка:

```typescript
for (let i = 0; i <= nums.length; i++) {
    console.log(nums[i]);
}
```

Здесь `i` доходит до `5`, и на последней итерации `nums[5]` — `undefined`.

Правильно:

```typescript
for (let i = 0; i < nums.length; i++) {
    console.log(nums[i]);
}
```

Запомните шаблон: **`i < n`**, а не `i <= n`.

### Строка — это тоже последовательность

Строку можно рассматривать как массив символов:

```typescript
const s = "hello";

console.log(s[0]);      // "h"
console.log(s[4]);      // "o"
console.log(s.length);  // 5
```

Поэтому почти всё, что работает для массива, работает и для строки: индексы, циклы, указатели.

## 1.3. Переменные

**Переменная** — это именованная ячейка памяти. В неё можно положить значение и потом заменить.

```typescript
let count = 0;   // создали переменную count со значением 0
count = count + 1; // теперь count = 1
count++;           // то же самое: count = count + 1
```

- `let` — значение можно менять;
- `const` — значение менять нельзя (но содержимое массива менять можно).

В алгоритмах на два указателя переменные-указатели — это обычные числа:

```typescript
let left = 0;
let right = nums.length - 1;
```

`left` и `right` — не «стрелки» и не «ссылки». Это **числа-индексы**. Когда мы говорим «указатель сдвинулся», мы имеем в виду «число увеличилось или уменьшилось».

## 1.4. Условия

Условие позволяет выполнить код только при определённом значении.

```typescript
if (nums[i] === 0) {
    console.log("Это ноль");
} else if (nums[i] > 0) {
    console.log("Положительное");
} else {
    console.log("Отрицательное");
}
```

Операторы сравнения:

| Оператор | Значение |
|----------|----------|
| `===` | равно |
| `!==` | не равно |
| `<`, `<=` | меньше, меньше или равно |
| `>`, `>=` | больше, больше или равно |

Почему `===`, а не `==`? В JavaScript `==` умеет неожиданно приводить типы (`"1" == 1` — истина). `===` сравнивает строго. В учебных алгоритмах всегда используйте `===`.

## 1.5. Циклы

Цикл повторяет действия, пока условие истинно.

### `for` — когда известно, сколько раз повторять

```typescript
for (let i = 0; i < 5; i++) {
    console.log(i); // 0, 1, 2, 3, 4
}
```

Разбор:

1. `let i = 0` — создаём счётчик.
2. `i < 5` — проверяем условие перед каждой итерацией.
3. Тело цикла.
4. `i++` — увеличиваем счётчик после итерации.
5. Снова проверяем условие.

Порядок важен: **условие проверяется до тела**, поэтому при `i = 5` тело уже не выполнится.

### `while` — когда важно только условие

```typescript
let i = 0;

while (i < 5) {
    console.log(i);
    i++;
}
```

`while` используют, когда указатели движутся по сложному правилу и заранее неизвестно, сколько шагов потребуется. Почти все решения на два указателя пишут через `while`.

### Бесконечный цикл

Если забыть сдвинуть указатель, условие никогда не станет ложным:

```typescript
let left = 0;
let right = 4;

while (left < right) {
    console.log("И тут мы застряли");
    // ни left, ни right не меняются
}
```

Это одна из самых частых ошибок. В каждом теле `while` должен быть шаг, который приближает условие к завершению.

## 1.6. Функция: вход, выход, побочный эффект

```typescript
function sumArray(nums: number[]): number {
    let sum = 0;

    for (let i = 0; i < nums.length; i++) {
        sum += nums[i];
    }

    return sum;
}
```

- Вход: `nums`.
- Выход: число.
- Локальная переменная `sum` живёт только внутри функции.

Функция может **менять входной массив**. Это называется побочным эффектом:

```typescript
function doubleAll(nums: number[]): void {
    for (let i = 0; i < nums.length; i++) {
        nums[i] = nums[i] * 2;
    }
}
```

После вызова `doubleAll(arr)` массив `arr` изменится. Это важно для темы «in-place» (раздел 1.8).

## 1.7. Сложность: сколько работы делает алгоритм

Нам нужно уметь сравнивать алгоритмы, не запуская их на секундомер. Секунды зависят от компьютера, языка и погоды. Поэтому считают **количество элементарных операций** как функцию от размера входа `n`.

Обозначение **O(...)** читается «о большое от...». Это оценка сверху: «растёт не быстрее, чем...».

### O(1) — постоянное время

Операция не зависит от `n`.

```typescript
const first = nums[0];
const last = nums[nums.length - 1];
```

Сколько бы элементов ни было в массиве, это одна операция.

### O(n) — линейное время

Один проход по массиву.

```typescript
let sum = 0;
for (let i = 0; i < nums.length; i++) {
    sum += nums[i];
}
```

Если `n = 1000`, будет примерно 1000 шагов. Если `n = 1 000 000` — примерно миллион. Время растёт пропорционально размеру.

### O(n²) — квадратичное время

Вложенные циклы, каждый по `n`:

```typescript
for (let i = 0; i < n; i++) {
    for (let j = 0; j < n; j++) {
        // ...
    }
}
```

Число шагов примерно `n × n`. При `n = 1000` это миллион операций, при `n = 10 000` — сто миллионов. Это уже медленно.

### Таблица для наглядности

| n | O(n) | O(n²) |
|---|------|-------|
| 10 | 10 | 100 |
| 100 | 100 | 10 000 |
| 1 000 | 1 000 | 1 000 000 |
| 10 000 | 10 000 | 100 000 000 |

Именно поэтому метод двух указателей ценен: он часто превращает O(n²) в O(n).

### Что мы не считаем

Константы и «младшие» слагаемые отбрасывают:

- `2n + 5` → O(n)
- `n² + 100n` → O(n²)
- `3` → O(1)

Нас интересует **характер роста** при больших `n`, а не точное число операций.

### Время и память — разные вещи

Алгоритм может быть быстрым по времени, но тратить много памяти. Обычно указывают две оценки:

- **Time complexity** — время.
- **Space complexity** — дополнительная память.

Пример:

```typescript
function copyArray(nums: number[]): number[] {
    const result: number[] = [];

    for (let i = 0; i < nums.length; i++) {
        result.push(nums[i]);
    }

    return result;
}
```

Время O(n), дополнительная память O(n) — мы создали новый массив.

## 1.8. In-place: изменение на месте

**In-place** означает: изменяем исходный массив, не создавая новый такого же размера.

```typescript
// Не in-place: создаём новый массив
function doubledCopy(nums: number[]): number[] {
    const result: number[] = [];
    for (let i = 0; i < nums.length; i++) {
        result.push(nums[i] * 2);
    }
    return result;
}

// In-place: меняем исходный массив
function doubleInPlace(nums: number[]): void {
    for (let i = 0; i < nums.length; i++) {
        nums[i] = nums[i] * 2;
    }
}
```

Зачем это нужно?

- Экономия памяти.
- Иногда условие прямо запрещает создавать новый массив.
- На собеседованиях проверяют, умеете ли вы работать с индексами, а не только с готовыми методами.

Дополнительная память O(1) означает: мы используем несколько переменных (`left`, `right`, `slow`), но не создаём массив, растущий вместе с `n`.

### Задачи, где возвращают длину, а не массив

В задачах на удаление элементов часто просят вернуть **длину** «полезной» части массива.

Пример: `[1, 1, 2]` после удаления дубликатов должна стать `[1, 2, ...]`, а вернуть нужно `2`.

Почему не весь массив? Потому что хвост может содержать «мусор» — старые значения, которые уже не важны. Проверяющий смотрит только на первые `k` элементов.

Это как записать в тетради новый список поверх старого: последние строки остались, но вы на них не смотрите.

## 1.9. Перебор, или «в лоб»

Самый простой способ решить задачу — проверить все варианты.

Пример: найти два числа с суммой `target`.

```typescript
function twoSumBruteForce(nums: number[], target: number): number[] {
    for (let i = 0; i < nums.length; i++) {
        for (let j = i + 1; j < nums.length; j++) {
            if (nums[i] + nums[j] === target) {
                return [i, j];
            }
        }
    }
    return [-1, -1];
}
```

Это правильно, но O(n²). При `n = 100 000` — до 10 миллиардов проверок.

**Перебор — это не плохо.** Это база:

1. Он всегда понятен.
2. Он даёт эталон, с которым можно сверять быстрое решение.
3. Он показывает, какие проверки дублируются.

Метод двух указателей — это оптимизация перебора: мы замечаем, что часть пар можно не проверять.

## 1.10. Как понять, что алгоритм правильный

Для простых алгоритмов достаточно прогнать примеры. Для двух указателей полезно уметь объяснять **инвариант**.

**Инвариант** — утверждение, которое истинно перед каждой итерацией цикла.

Пример для поиска максимума:

```typescript
let max = nums[0];

for (let i = 1; i < nums.length; i++) {
    if (nums[i] > max) {
        max = nums[i];
    }
}
```

Инвариант: «`max` — наибольшее значение среди `nums[0] ... nums[i-1]`».

- Перед первой итерацией: `max = nums[0]`, диапазон `[0, 0)` пуст, но база корректна.
- На каждом шаге мы сравниваем новый элемент и обновляем `max`.
- После последней итерации `max` — максимум всего массива.

Инвариант — это не формальность ради формальности. Он позволяет ответить на вопрос: **«Почему алгоритм не пропустит правильный ответ?»**

В следующих главах мы будем формулировать инвариант для каждого паттерна.

## 1.11. Мини-практика

### Задание 1

Что выведет код?

```typescript
const nums = [5, 10, 15];
for (let i = 0; i <= nums.length; i++) {
    console.log(nums[i]);
}
```

<details>
<summary>Ответ</summary>

`5`, `10`, `15`, `undefined`. На последней итерации `i = 3`, а последний индекс — `2`.

</details>

### Задание 2

Определите сложность:

```typescript
let count = 0;
for (let i = 0; i < n; i++) {
    for (let j = 0; j < n; j++) {
        if (nums[i] + nums[j] === 0) count++;
    }
}
```

<details>
<summary>Ответ</summary>

O(n²): два вложенных цикла по `n`.

</details>

### Задание 3

Что делает функция?

```typescript
function mystery(nums: number[]): number {
    let result = 0;
    for (let i = 0; i < nums.length; i++) {
        if (nums[i] % 2 === 0) result++;
    }
    return result;
}
```

<details>
<summary>Ответ</summary>

Считает количество чётных чисел. Сложность O(n), дополнительная память O(1).

</details>

### Задание 4

Почему `nums[nums.length]` — плохая идея?

<details>
<summary>Ответ</summary>

Потому что последний индекс — `nums.length - 1`. Обращение на единицу дальше выходит за границы массива и даёт `undefined` (или ошибку в других языках).

</details>

## Что запомнить из главы

1. Индекс начинается с `0`, последний индекс — `n - 1`.
2. `while` используют, когда число шагов заранее неизвестно.
3. O(n) — один проход, O(n²) — вложенные проходы.
4. In-place — менять исходный массив, дополнительная память O(1).
5. Перебор — база; оптимизация — это отказ от лишних проверок.
6. Инвариант объясняет, почему алгоритм не пропускает ответ.
