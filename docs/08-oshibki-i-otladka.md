# Глава 8. Типичные ошибки и отладка

Эта глава — про то, что делать, когда решение «вроде правильное», но тесты падают. Здесь собраны ошибки, которые встречаются чаще всего, и пошаговый метод отладки.

---

## 8.1. Двенадцать типичных ошибок

### Ошибка 1. Выход за границы

```typescript
// Неправильно
for (let i = 0; i <= nums.length; i++) {
    console.log(nums[i]); // на последнем шаге nums[n] === undefined
}
```

```typescript
// Правильно
for (let i = 0; i < nums.length; i++) { ... }
```

Правило: последний индекс — `length - 1`.

### Ошибка 2. Забыть сдвинуть указатель (бесконечный цикл)

```typescript
while (left < right) {
    const sum = nums[left] + nums[right];

    if (sum === target) return [left, right];
    // забыли left++ / right--
}
```

Если ни один указатель не двигается, условие никогда не станет ложным. В каждом теле цикла должен быть шаг.

### Ошибка 3. Двигать оба указателя сразу

```typescript
// Неправильно для поиска пары
if (sum < target) {
    left++;
    right--;
}
```

Так вы пропускаете пары. В задачах на пару за один шаг двигается **ровно один** указатель.

### Ошибка 4. Перепутать направление движения

В TwoSumSorted:

- сумма **меньше** target → нужно **увеличить** → `left++`;
- сумма **больше** target → нужно **уменьшить** → `right--`.

Частая ошибка — делать наоборот, потому что «маленькая сумма — надо уменьшить». Нет: маленькая сумма означает, что не хватает величины.

### Ошибка 5. Неверное условие цикла

| Задача | Условие | Если ошибиться |
|--------|---------|----------------|
| Пара | `left < right` | `<=` возьмёт один элемент дважды |
| Слияние | `i < n && j < m` | `||` выйдет за границы |
| Backspace | `si >= 0 || ti >= 0` | `&&` пропустит хвост |
| Squares | `pos >= 0` | `pos > 0` потеряет первый элемент |

### Ошибка 6. Забыть остаток при слиянии

```typescript
while (i < n && j < m) { ... }
return result; // потеряли хвост одного из массивов
```

После основного цикла нужны два `while` для остатков.

### Ошибка 7. Неверный смысл `slow`

В задаче 1 `slow` — **индекс** последнего уникального, ответ `slow + 1`.
В задаче 8 `slow` — **количество** записанных, ответ `slow`.

Если перепутать, решение будет ошибаться на единицу. Всегда выписывайте: «`slow` — это индекс или количество?»

### Ошибка 8. Увеличить `slow` до записи

```typescript
// Неправильно
slow++;
nums[slow] = nums[fast];
```

Вы оставляете «дырку» на позиции старого `slow`. Правильно:

```typescript
nums[slow] = nums[fast];
slow++;
```

### Ошибка 9. Перезапись вместо swap

В MoveZeroes перезапись без заполнения хвоста нулями теряет нули:

```typescript
// Неправильно: нули не сохраняются
nums[slow] = nums[fast];
```

Нужен либо swap, либо второй цикл, который заполнит хвост нулями.

### Ошибка 10. Сравнение не с тем элементом

Для «не более K повторов» нужно сравнивать с `nums[slow - K]`, а не с `nums[slow - 1]`. Иначе разрешите только один повтор.

### Ошибка 11. Забыть про пустой вход

```typescript
let max = nums[0]; // упадёт на []
```

Проверяйте `if (nums.length === 0)` в начале, если обращаетесь к элементам.

### Ошибка 12. Использовать монотонность без сортировки

Правило «сумма меньше → left++» работает только на отсортированном массиве. На неотсортированном оно может пропустить ответ.

## 8.2. Чек-лист граничных случаев

Перед отправкой решения проверьте:

- [ ] пустой массив / пустая строка;
- [ ] один элемент;
- [ ] два элемента;
- [ ] все элементы одинаковые;
- [ ] все элементы разные;
- [ ] отрицательные числа;
- [ ] нули;
- [ ] ответа не существует;
- [ ] ответ — первый и последний элементы;
- [ ] указатели встречаются ровно в центре;
- [ ] чётная и нечётная длина.

### Пример: что ломается на границах

| Задача | Пустой вход | Один элемент | Все одинаковые |
|--------|-------------|--------------|----------------|
| RemoveDuplicates | вернуть 0 | вернуть 1 | вернуть 1 |
| IsPalindrome | true | true | true |
| TwoSumSorted | `[-1,-1]` | `[-1,-1]` | если target = 2×значение, но нужны два разных индекса — в массиве из одного элемента ответа нет |
| Container | 0 | 0 | площадь = высота × расстояние |
| Merge | вернуть второй | вернуть второй | слить все |
| LongestPalindrome | 0 | 1 | длина строки |

## 8.3. Метод трассировки

Трассировка — это ручное выполнение алгоритма с записью состояния.

### Шаблон таблицы

| Шаг | Указатель 1 | Указатель 2 | Значения | Условие | Действие | Структура |
|-----|-------------|-------------|----------|---------|----------|-----------|
| 0 | | | | | | |
| 1 | | | | | | |
| 2 | | | | | | |

### Пример для TwoSumSorted

Вход: `[2, 7, 11, 15]`, target = 9.

| Шаг | left | right | nums[left] | nums[right] | sum | Решение | Массив |
|-----|------|-------|------------|-------------|-----|---------|--------|
| 0 | 0 | 3 | 2 | 15 | 17 | right-- | без изменений |
| 1 | 0 | 2 | 2 | 11 | 13 | right-- | без изменений |
| 2 | 0 | 1 | 2 | 7 | 9 | ответ | — |

Если таблица расходится с кодом — вы нашли ошибку.

### Правило трёх примеров

Всегда проверяйте на:

1. маленьком примере из условия;
2. граничном примере (пусто/один элемент);
3. «злом» примере (все одинаковые, отрицательные, ответ в конце).

## 8.4. Отладочная печать

Самый простой инструмент — вывести состояние внутри цикла.

```typescript
while (left < right) {
    const sum = nums[left] + nums[right];
    console.log({ left, right, leftVal: nums[left], rightVal: nums[right], sum });

    if (sum === target) return [left, right];
    if (sum < target) left++;
    else right--;
}
```

Что смотреть:

- указатели не выходят за границы;
- указатели не «стоят» на месте несколько итераций;
- сумма меняется в ожидаемую сторону;
- цикл завершается.

### Отладочная печать для `slow`/`fast`

```typescript
console.log({
    fast,
    slow,
    fastVal: nums[fast],
    slowVal: nums[slow],
    array: [...nums],
});
```

Важно: `[...nums]` копирует массив на момент печати. Если печатать `nums` напрямую, консоль может показать уже изменённый массив.

## 8.5. Проверка инварианта

Инвариант — это утверждение, которое должно быть истинно на каждой итерации. Добавьте проверку в код (во время отладки):

```typescript
// Для RemoveDuplicates
for (let fast = 1; fast < nums.length; fast++) {
    // Инвариант: nums[0..slow] — уникальные элементы из nums[0..fast-1]
    if (nums[fast] !== nums[slow]) {
        slow++;
        nums[slow] = nums[fast];
    }
}
```

Если инвариант нарушается — ошибка произошла раньше, в правиле движения.

### Инварианты для каждого паттерна

| Паттерн | Инвариант |
|---------|-----------|
| Быстрый/медленный | первые `slow` элементов — корректный ответ на просмотренной части |
| С двух сторон | все пары за пределами `[left, right]` уже проверены или отброшены |
| Два массива | все элементы до `i` и `j` уже обработаны |
| От центра | `s[left+1..right-1]` — палиндром |

## 8.6. Как искать ошибку, если тест упал

### Шаг 1. Прочитайте, какой именно тест упал

В выводе теста есть вход, ожидаемый результат и фактический.

```text
[FAIL] Case #3: [[1,1,2,2],[2,2]]
       Expected: [2]
       Got:      [2,2]
```

Это уже подсказка: проблема с дубликатами.

### Шаг 2. Воспроизведите вручную

Возьмите этот вход и прогоните алгоритм на бумаге. Найдите шаг, где фактическое поведение расходится с ожидаемым.

### Шаг 3. Сформулируйте гипотезу

Не «попробую поменять вот здесь», а «я думаю, ошибка в том, что при равенстве мы не пропускаем дубликаты».

### Шаг 4. Проверьте одну гипотезу

Измените **одну** строку. Перезапустите тесты. Не меняйте сразу пять мест.

### Шаг 5. Если не помогло — вернитесь назад

Откатите изменение. Иначе накопите несколько ошибок и потеряете причину.

### Правило трёх попыток

Если три гипотезы подряд не сработали:

1. остановитесь;
2. перечитайте условие;
3. проверьте, тот ли паттерн вы выбрали;
4. только потом продолжайте.

## 8.7. Частые ошибки по задачам

| Задача | Что чаще всего ломается |
|--------|--------------------------|
| RemoveDuplicates | `return slow` вместо `slow + 1`; старт `slow = 1` |
| RemoveDuplicates2 | сравнение с `slow - 1` вместо `slow - 2` |
| MoveZeroes | перезапись без заполнения нулей |
| SortArrayByParity | ожидание устойчивого порядка |
| TwoSumSorted | движение не того указателя; `<=` в условии |
| TwoSumLessThanK | забыть обновить `best`; вернуть 0 вместо -1 |
| Container | двигать высокую стенку; забыть `min` |
| ThreeSum | дубликаты троек; выход за границу в `while` |
| Merge | потерять остаток |
| Intersection | дубликаты в ответе |
| FindDifference | не пропустить повторы |
| IsSubsequence | двигать `si` без совпадения |
| ReverseString | `<=` и лишний обмен |
| ValidPalindromeRemoval | рекурсивно удалять больше одного символа |
| Backspace | идти с начала; неверное условие `||`/`&&` |
| Squares | заполнять результат слева направо |
| LongestPalindrome | проверять только нечётные центры |

## 8.9. Упражнение: найдите ошибку

### Фрагмент 1

```typescript
function removeDuplicates(nums: number[]): number {
    let slow = 0;
    for (let fast = 1; fast < nums.length; fast++) {
        if (nums[fast] !== nums[slow]) {
            slow++;
            nums[slow] = nums[fast];
        }
    }
    return slow;
}
```

<details>
<summary>Ответ</summary>

Для `[1, 1, 2]` вернёт `1` вместо `2`. Нужно `return slow + 1`, потому что `slow` — индекс, а не количество.

</details>

### Фрагмент 2

```typescript
function twoSum(nums: number[], target: number): number[] {
    let left = 0;
    let right = nums.length - 1;

    while (left <= right) {
        const sum = nums[left] + nums[right];
        if (sum === target) return [left, right];
        if (sum < target) left++;
        else right--;
    }
    return [-1, -1];
}
```

<details>
<summary>Ответ</summary>

Две проблемы:
1. `left <= right` позволяет взять один и тот же индекс дважды (нужно `<`).
2. Нет проверки, что массив отсортирован; алгоритм корректен только для отсортированного.

</details>

### Фрагмент 3

```typescript
function moveZeroes(nums: number[]): number[] {
    let slow = 0;
    for (let fast = 0; fast < nums.length; fast++) {
        if (nums[fast] !== 0) {
            nums[slow] = nums[fast];
            slow++;
        }
    }
    return nums;
}
```

<details>
<summary>Ответ</summary>

Нули не заполняются в хвосте. Для `[0, 1, 0, 3, 12]` получится `[1, 3, 12, 3, 12]`. Нужен swap или второй цикл, заполняющий `nums[slow..]` нулями.

</details>

### Фрагмент 4

```typescript
function merge(a: number[], b: number[]): number[] {
    const result: number[] = [];
    let i = 0;
    let j = 0;

    while (i < a.length && j < b.length) {
        if (a[i] < b[j]) {
            result.push(a[i]);
            i++;
        } else {
            result.push(b[j]);
            j++;
        }
    }

    return result;
}
```

<details>
<summary>Ответ</summary>

Потерян остаток. Для `[1, 2]` и `[3, 4]` вернёт `[1, 2]` вместо `[1, 2, 3, 4]`.

</details>

## Что запомнить из главы

1. Выход за границы — самая частая ошибка; проверяйте `i < n`.
2. В каждом цикле должен быть шаг, приближающий завершение.
3. В задачах на пару двигается один указатель, не оба.
4. Следите за смыслом `slow`: индекс или количество.
5. Трассировка на бумаге быстрее, чем десять перезапусков.
6. Меняйте одну гипотезу за раз.
7. Проверяйте пустой вход, один элемент, дубликаты и отсутствие ответа.
