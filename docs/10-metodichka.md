# Глава 10. Методичка для преподавателя

Эта глава — не про алгоритмы, а про то, как объяснять их студентам, которые никогда не решали алгоритмические задачи.

Цель курса: к концу студент **самостоятельно** определяет паттерн, пишет решение и объясняет, почему оно не пропускает ответ.

---

## 10.1. Портрет студента

Предполагаем, что студент:

- знает, что такое переменная, условие и цикл;
- видел массивы, но не уверенно работает с индексами;
- не знает, что такое O(n);
- не решал задачи на собеседованиях;
- может растеряться от слов «in-place», «инвариант», «указатель».

Чего **не** предполагаем:

- знания C/C++ и указателей;
- опыта с LeetCode;
- понимания рекурсии;
- математической подготовки сверх школьной.

---

## 10.2. Результаты обучения

После курса студент:

1. Объясняет, что такое индекс и почему последний индекс — `n - 1`.
2. Считает сложность простого цикла и вложенных циклов.
3. Различает четыре семейства задач на два указателя.
4. Пишет шаблон для каждого семейства по памяти.
5. Решает 20 задач из практикума.
6. Формулирует инвариант для своего решения.
7. Находит ошибку по трассировке, а не перебором случайных правок.

## 10.4. План занятия 1: основы

### Цель

Студент понимает индекс, цикл и простую сложность. Без этого дальше будет больно.

### Ход занятия (90 минут)

**0–10 мин. Разминка.**

Спросите: «Что выведет этот код?»

```typescript
const a = [10, 20, 30];
for (let i = 0; i <= a.length; i++) {
    console.log(a[i]);
}
```

Дайте 2 минуты подумать, затем разберите. Пусть кто-то скажет «undefined» и объяснит почему.

**10–30 мин. Индекс как расстояние.**

Нарисуйте на доске:

```text
[10] [20] [30] [40]
  0    1    2    3
```

Спросите:

- Чему равен `a[2]`?
- Чему равен последний индекс?
- Что будет при `a[4]`?
- Почему нумерация с нуля?

**30–50 мин. Циклы.**

Попросите студентов написать цикл, который печатает все элементы. Затем — в обратном порядке. Затем — только чётные.

Типичная ошибка: `i <= length`. Покажите её и попросите найти.

**50–70 мин. Сложность.**

Сравните два кода:

```typescript
// O(n)
for (let i = 0; i < n; i++) { ... }

// O(n²)
for (let i = 0; i < n; i++) {
    for (let j = 0; j < n; j++) { ... }
}
```

Спросите: «Во сколько раз медленнее второй при n = 1000?» (в 1000 раз). «А при n = 10 000?» (в 10 000 раз).

**70–85 мин. In-place.**

Покажите разницу между созданием нового массива и изменением старого. Спросите, почему иногда просят `return length`, а не массив.

**85–90 мин. Домашнее задание.**

- 5 задач на индексы и циклы;
- прочитать главу 1;
- письменно ответить, чем `i < n` отличается от `i <= n`.

### Вопросы для проверки

1. Почему последний индекс — `n - 1`?
2. Что такое O(n)?
3. Почему вложенные циклы — O(n²)?
4. Что значит in-place?
5. Почему `return length` может быть достаточно?

## 10.5. План занятия 2: быстрый и медленный

### Цель

Студент понимает модель «читатель/писатель» и может написать шаблон.

### Ход занятия

**0–10 мин. Повторение.**

Спросите: «Как удалить элементы из массива, не создавая новый?» Пусть предложат наивный вариант.

**10–25 мин. Аналогия конвейера.**

Нарисуйте:

```text
читатель →
[ 3, 1, 2, 4, 5, 6 ]
 ↑
писатель
```

Объясните: читатель смотрит на всё, писатель кладёт нужное в начало.

**25–45 мин. Задача 1 вместе.**

Решайте на доске, но не пишите код сразу. Сначала:

1. Определите смысл `slow` и `fast`.
2. Прогоните `[1, 1, 2]` вручную.
3. Только потом напишите код.

Спросите: «Почему сравниваем с `nums[slow]`, а не с `nums[fast - 1]`?» (Потому что `slow` — последний сохранённый уникальный.)

**45–65 мин. Самостоятельно задачи 7 и 8.**

Дайте 10 минут на каждую. Затем разберите различия: swap vs перезапись.

**65–80 мин. Задача 10.**

Начните с вопроса: «Что изменится, если разрешить два повтора?» Подведите к `slow - 2`.

**80–90 мин. Итог и домашнее задание.**

Дома: задачи 9, 10 и дополнительная задача на K повторов.

### Вопросы для проверки

1. Что означает `slow` в задаче 1?
2. Почему ответ `slow + 1`, а не `slow`?
3. Когда нужен swap, а когда перезапись?
4. Почему в задаче 10 сравнение с `slow - 2`?

## 10.6. План занятия 3: с двух сторон

### Цель

Студент понимает монотонность и умеет объяснять, почему можно отбросить край.

### Ход занятия

**0–10 мин. Разминка: палиндром.**

Спросите, как проверить палиндром, не создавая новую строку. Подведите к двум указателям.

**10–25 мин. Задача 3.**

Напишите вместе. Обсудите `left < right` vs `<=`.

**25–50 мин. Задача 2.**

Это ключевая задача занятия. Не давайте правило сразу. Спросите:

- «Если сумма больше target, что можно сказать про правый указатель?»
- «Можно ли с этим правым указателем получить target, двигая левый?»
- «Почему?»

Дождитесь формулировки: «Все числа левее меньше, поэтому сумма только уменьшится».

**50–70 мин. Задача 5 (контейнер).**

Сначала дайте нарисовать контейнеры. Спросите: «Какую стенку двигать и почему?» Многие скажут «высокую». Разберите контрпример.

**70–85 мин. Задача 19 (квадраты).**

Спросите: «Где может быть самый большой квадрат?» Подведите к краям и записи с конца.

**85–90 мин. Домашнее задание.**

Задачи 4 и 16; письменно объяснить, почему в контейнере двигают низкую стенку.

### Вопросы для проверки

1. Почему в TwoSumSorted можно отбросить правый указатель при `sum > target`?
2. Почему в контейнере двигают низкую стенку?
3. Почему в squares результат заполняется с конца?
4. Когда `left < right`, а когда `left <= right`?

## 10.7. План занятия 4: два массива и распознавание

### Цель

Студент сливает, пересекает и различает паттерны по условию.

### Ход занятия

**0–15 мин. Слияние.**

Начните с вопроса: «Как слить два отсортированных массива?» Пусть предложат перебор. Покажите, почему он O(n²) и как указатели дают O(n + m).

**15–30 мин. Пересечение.**

Сравните задачи 12 и 15. Спросите: «Чем отличается ответ?» (повторы). «Что меняется в коде?» (проверка на дубликат).

**30–45 мин. Difference и subsequence.**

Дайте самостоятельно, затем разберите граничные случаи: пустой второй массив, `j >= length`, `si` vs `ti`.

**45–65 мин. ThreeSum.**

Покажите сведение: «Тройка — это фиксация + пара». Прогоните пример на доске.

**65–80 мин. Распознавание.**

Дайте 8 коротких условий (из главы 7) и попросите определить паттерн за 1 минуту каждое. Обсудите ошибки.

**80–90 мин. Итог курса.**

Соберите карту:

```text
удалить → A
пара/палиндром → B
два массива → C
подстрока-палиндром → D
тройка → фиксация + B
```

Дома: практикум, задачи 17, 18, 20.

## 10.8. Как объяснять сложность

Не начинайте с формального определения. Начните с вопроса:

> «Если элементов станет в 10 раз больше, во сколько раз дольше будет работать алгоритм?»

- O(1) — так же;
- O(n) — в 10 раз;
- O(n²) — в 100 раз.

Затем покажите таблицу:

| n | O(n) | O(n²) |
|---|------|-------|
| 10 | 10 | 100 |
| 1 000 | 1 000 | 1 000 000 |

Только после этого вводите запись O(...).

### Частая путаница

Студенты думают, что O(n) — это «ровно n операций». Объясните: это **характер роста**, константы не важны.

Студенты думают, что O(n²) всегда плохо. Объясните: при маленьких `n` разница несущественна, но на больших данных — критична.

## 10.9. Аналогии, которые работают

| Понятие | Аналогия |
|---------|----------|
| Индекс | Номер дома на улице, нумерация с нуля |
| Указатель | Палец, которым вы показываете на элемент |
| Быстрый/медленный | Читатель и писатель на конвейере |
| С двух сторон | Два человека идут навстречу с концов шеренги |
| Два массива | Два слияния двух очередей |
| От центра | Круги на воде от брошенного камня |
| In-place | Переписать список поверх старого |
| Инвариант | Обещание, которое выполняется на каждом шаге |

### Аналогия, которую лучше не использовать

«Указатель — это стрелка в памяти». Для студентов без C/C++ это создаёт ложное впечатление. Говорите: «указатель — это число-индекс».

## 10.10. Типичные ошибки студентов и реакции

### «Я не понимаю, зачем второй указатель»

Ответ: покажите на примере перебора, сколько пар проверяется зря. Затем покажите, как один указатель «отбрасывает» группу.

### «Я запомнил код, но не понимаю»

Ответ: попросите объяснить смысл каждой переменной. Если не может — вернитесь к трассировке. Запоминание без понимания не переносится на другие задачи.

### «У меня работает на примере, но не проходит тесты»

Ответ: граничные случаи. Пустой вход, один элемент, все одинаковые. Покажите, как трассировать.

### «Я двигаю оба указателя, так быстрее»

Ответ: быстрее, но неправильно. Покажите пример, где пара пропускается.

### «Почему не `<=`?»

Ответ: зависит от задачи. Для пары — `<`, чтобы не взять один индекс дважды. Для реверса — `<`, чтобы не менять средний элемент. Для некоторых задач — `<=`. Всегда объясняйте через смысл.

### «Я не знаю, какой паттерн выбрать»

Ответ: пять вопросов из главы 7. Начните с «сколько последовательностей» и «отсортировано ли».

### «Я не понимаю условие»

Ответ: попросите пересказать условие своими словами и привести свой пример входа/выхода. Часто проблема не в алгоритме, а в чтении.

---

## 10.11. Как вести разбор задачи

Используйте одинаковую структуру каждый раз:

1. **Условие своими словами.** Что дано, что вернуть.
2. **Пример.** Маленький, 3–5 элементов.
3. **Наивное решение.** Перебор. Его сложность.
4. **Идея оптимизации.** Что можно не проверять.
5. **Смысл указателей.** Одно предложение на каждый.
6. **Правило движения.** Кто и когда двигается.
7. **Трассировка.** Таблица на 3–5 шагов.
8. **Код.** Только теперь.
9. **Граничные случаи.**
10. **Сложность.**
11. **Инвариант.** Почему не пропустим ответ.

Не пропускайте шаги 1–5. Студенты часто хотят сразу код — это путь к запоминанию без понимания.

## 10.12. Работа на доске

### Схема для семейства A

```text
fast →
[ 3, 1, 2, 4, 5, 6 ]
 ↑
slow

slow — куда писать
fast — что читаем
```

### Схема для семейства B

```text
left →          ← right
[ 2, 7, 11, 15 ]

область [left, right] — кандидаты
```

### Схема для семейства C

```text
i
↓
[1, 3, 5]
[2, 4, 6]
       ↑
       j
```

### Схема для D

```text
    ← L R →
[ b, a, b, a, d ]
      ↑ ↑
   центр
```

### Совет

Рисуйте указатели **под** массивом, а не над. Так проще стирать и двигать.

## 10.14. Критерии оценки

### Решение задачи (10 баллов)

| Критерий | Баллы |
|----------|-------|
| Правильность на тестах | 4 |
| Объяснение идеи и смысла указателей | 2 |
| Корректные граничные случаи | 1 |
| Сложность определена верно | 1 |
| Код читаем, имена осмысленные | 1 |
| Может объяснить, что отбрасывается | 1 |

### Устный ответ (5 баллов)

1. Что такое индекс? (1)
2. Почему последний индекс `n - 1`? (1)
3. Чем O(n) отличается от O(n²)? (1)
4. Когда нужен swap, а когда перезапись? (1)
5. Как определить паттерн по условию? (1)

### Что считать «отлично»

Студент не просто пишет код, а:

- объясняет, почему правило движения корректно;
- сам находит ошибку по трассировке;
- переносит шаблон на новую задачу;
- различает похожие паттерны.

## 10.17. Главный педагогический принцип

> **Не показывайте решение. Создайте ситуацию, в которой студент сам упрётся в проблему перебора и захочет её решить.**

Вопросы работают лучше объяснений:

- «Сколько пар проверяет перебор?»
- «Можно ли не проверять эту пару?»
- «Что мы знаем про числа правее?»
- «Почему это безопасно?»

Если студент сам сформулировал, что можно отбросить, — он понял метод. Если только запомнил код — он решит одну задачу и не решит следующую.
