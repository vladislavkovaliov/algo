# Глава 2. Метод двух указателей: главная идея

В главе 1 мы научились работать с массивом по индексу. Теперь добавим второй индекс — и получим один из самых мощных приёмов в алгоритмах.

---

## 2.1. Идея на пальцах

Представьте, что перед вами длинная полка с коробками, и вам нужно найти две коробки, которые вместе весят ровно 100 кг.

Самый простой способ — брать каждую коробку и сравнивать со всеми остальными. Это перебор.

Другой способ: поставить двух помощников — одного у левого края полки, другого у правого. Они смотрят на свои коробки, сравнивают сумму с 100 и **делают вывод, кому из них двигаться дальше**.

- Сумма слишком маленькая → нужно взять что-то тяжелее. Левый помощник (если полка отсортирована по весу) идёт вправо.
- Сумма слишком большая → нужно что-то легче. Правый идёт влево.

Каждый шаг **отбрасывает целую группу вариантов**. Помощники встречаются в середине — и всё, задача решена.

Вот это и есть метод двух указателей.

> **Два указателя — это два индекса, которые движутся по данным по правилу, позволяющему не рассматривать лишние варианты.**

Слово «указатель» здесь не означает указатель из C/C++. Это просто **переменная, в которой хранится индекс**.

```typescript
let left = 0;                 // указатель на начало
let right = nums.length - 1;  // указатель на конец
```

---

## 2.2. Почему это быстрее перебора

Перебор проверяет **все пары**:

```text
n = 5
пары: (0,1) (0,2) (0,3) (0,4)
      (1,2) (1,3) (1,4)
      (2,3) (2,4)
      (3,4)
```

Количество пар — `n × (n - 1) / 2`, то есть O(n²).

Два указателя проверяют **не более 2n позиций**: каждый указатель проходит массив максимум один раз.

```text
left  →→→→→
right ←←←←←
```

Они не возвращаются назад. Это ключевое свойство: **монотонность**. Каждый шаг уменьшает область поиска.

| Подход | Время | Пример при n = 100 000 |
|--------|-------|------------------------|
| Перебор пар | O(n²) | ~5 000 000 000 проверок |
| Два указателя | O(n) | ~200 000 шагов |

Разница не в «оптимизации на 10%», а в том, что задача становится решаемой.

## 2.3. Четыре семейства задач

Важно понять: «два указателя» — это не один шаблон, а **семейство приёмов**. У них общая идея, но разные правила движения.

### Семейство A. Быстрый и медленный (same direction)

Оба указателя движутся слева направо, но с разными ролями.

```text
slow
 ↓
[1, 1, 2, 3, 3, 4]
    ↑
   fast
```

- `fast` — **читатель**: перебирает все элементы.
- `slow` — **писатель**: показывает, куда записать следующий «полезный» элемент.

Применяется, когда нужно:
- удалить элементы;
- убрать дубликаты;
- сдвинуть нули;
- разделить массив на группы.

Задачи: 1, 7, 8, 9, 10.

### Семейство B. С двух сторон (opposite direction)

Указатели стоят на краях и движутся навстречу.

```text
left →        ← right
[2, 7, 11, 15]
```

Применяется, когда:
- массив отсортирован;
- нужно сравнить симметричные элементы;
- нужно сузить область поиска;
- нужно развернуть массив.

Задачи: 2, 3, 4, 5, 16, 19 (частично).

### Семейство C. По указателю на каждый массив

Один указатель в первом массиве, второй — во втором.

```text
i
↓
[1, 3, 5]
[2, 4, 6]
       ↑
       j
```

Применяется, когда:
- даны две последовательности;
- нужно слить, сравнить, найти общее;
- обе последовательности отсортированы.

Задачи: 11, 12, 13, 14, 15.

### Семейство D. Расширение от центра

Указатели начинают в центре (или в одной точке) и расходятся в стороны.

```text
    ← L R →
[ b, a, b, a, d ]
      ↑ ↑
```

Применяется для палиндромов:
- проверка подстроки;
- поиск самой длинной подстроки-палиндрома.

Задачи: 17 (частично), 18 (с конца), 20.

### Сводная таблица

| Семейство | Старт | Движение | Типичный вопрос задачи |
|-----------|-------|----------|------------------------|
| A. Быстрый/медленный | `slow = 0`, `fast = 0` | слева направо | «Удали/сдвинь/отфильтруй» |
| B. С двух сторон | `left = 0`, `right = n-1` | навстречу | «Найди пару/границу в отсортированном» |
| C. По указателю на массив | `i = 0`, `j = 0` | каждый по своему массиву | «Слей/сравни две последовательности» |
| D. От центра | `left = center`, `right = center` | расходятся | «Палиндром» |

## 2.4. Универсальный рецепт решения

Не начинайте с кода. Ответьте на семь вопросов.

### Вопрос 1. Что дано и что нужно вернуть?

Пример: «дан отсортированный массив, вернуть индексы двух чисел с суммой `target`».

Это определяет, можно ли менять вход и что считать результатом.

### Вопрос 2. Что означает каждый указатель?

Самый важный вопрос. Указатель без смысла — это просто число, которое двигают наугад.

Примеры смыслов:

- `slow` — «граница уже обработанной полезной части»;
- `fast` — «текущий проверяемый элемент»;
- `left` — «самый левый кандидат»;
- `right` — «самый правый кандидат»;
- `i` — «текущий элемент первого массива»;
- `j` — «текущий элемент второго массива».

Если вы можете объяснить смысл указателя одним предложением, вы на правильном пути.

### Вопрос 3. Где указатели начинают?

- Оба в начале — семейство A или C.
- На краях — семейство B.
- В центре — семейство D.

### Вопрос 4. Когда и какой указатель двигать?

Это правило должно опираться на данные, а не на «попробуем так».

Пример: в отсортированном массиве

```typescript
if (sum < target) {
    left++;   // нужно увеличить сумму
} else if (sum > target) {
    right--;  // нужно уменьшить сумму
}
```

### Вопрос 5. Когда остановиться?

- `while (left < right)` — указатели встретились.
- `while (left <= right)` — нужно обработать и средний элемент.
- `while (i < nums1.length && j < nums2.length)` — один массив закончился.

Ошибка в условии цикла — источник бесконечных циклов и пропущенных элементов.

### Вопрос 6. Что мы гарантированно не пропустим?

Это инвариант. Например:

> «Все пары, которые мы уже отбросили, не могут дать ответ».

Если не можете сформулировать — скорее всего, правило движения неверное.

### Вопрос 7. Какие граничные случаи?

- пустой массив;
- один элемент;
- два элемента;
- все элементы одинаковые;
- отрицательные числа;
- ответа не существует;
- указатели встретились.

Проверьте их **до** отправки решения.

## 2.5. Шаблоны кода

### Шаблон A: быстрый и медленный

```typescript
function filterTemplate(nums: number[]): number {
    let slow = 0;

    for (let fast = 0; fast < nums.length; fast++) {
        if (/* nums[fast] нужно сохранить */) {
            nums[slow] = nums[fast];
            slow++;
        }
    }

    return slow; // длина полезной части
}
```

Смысл: `fast` читает всё, `slow` пишет только нужное.

### Шаблон B: с двух сторон

```typescript
function oppositeTemplate(nums: number[]): void {
    let left = 0;
    let right = nums.length - 1;

    while (left < right) {
        // 1. посмотреть на nums[left] и nums[right]
        // 2. принять решение
        // 3. сдвинуть один или оба указателя
        left++;
        right--;
    }
}
```

Смысл: область `[left, right]` — это множество ещё не проверенных кандидатов. Она всё время сужается.

### Шаблон C: по указателю на массив

```typescript
function twoArraysTemplate(a: number[], b: number[]): number[] {
    const result: number[] = [];
    let i = 0;
    let j = 0;

    while (i < a.length && j < b.length) {
        if (a[i] < b[j]) {
            i++;
        } else if (a[i] > b[j]) {
            j++;
        } else {
            result.push(a[i]);
            i++;
            j++;
        }
    }

    return result;
}
```

Смысл: на каждом шаге сравниваем текущие элементы и двигаем тот указатель, который «отстаёт».

### Шаблон D: расширение от центра

```typescript
function expandTemplate(s: string, left: number, right: number): number {
    while (left >= 0 && right < s.length && s[left] === s[right]) {
        left--;
        right++;
    }

    return right - left - 1; // длина палиндрома
}
```

Смысл: пока символы совпадают, расширяем границы. Как только перестали — возвращаем длину последнего совпавшего отрезка.

## 2.6. Когда метод не работает

Два указателя — не универсальная таблетка. Вот ситуации, где нужно быть осторожным.

### Массив не отсортирован, а вы двигаете указатели по значению

Задача: найти два числа с суммой `target` в **неотсортированном** массиве.

Если поставить `left = 0`, `right = n - 1` и двигать по правилу «сумма меньше — left++», это не сработает: справа может стоять маленькое число, а слева — большое. Отсортированность даёт монотонность, на которой держится вывод.

Для неотсортированного массива:
- либо сначала сортируйте (если можно менять порядок) — O(n log n);
- либо используйте хеш-таблицу — O(n) по времени, O(n) по памяти.

### Нужно вернуть исходные индексы, а вы сортируете

Сортировка меняет позиции. Если задача просит индексы в исходном массиве, сортировать нельзя (или нужно хранить пары «значение + исходный индекс»).

### Указатели должны иногда двигаться назад

Если правило требует возврата, метод теряет линейность. Тогда это уже другой приём (например, динамическое программирование или хеш-таблица).

### Нужно рассмотреть все подмассивы

Два указателя хорошо работают, когда свойство **монотонно**: при движении в одну сторону сумма/длина/условие меняются предсказуемо. Если свойство «прыгает», метод может пропустить ответ.

## 2.7. Как отличить два указателя от скользящего окна

Их часто путают. Разница в вопросе, на который отвечает алгоритм.

| Два указателя | Скользящее окно |
|---------------|-----------------|
| Часто ищет **пару/тройку/границу** | Ищет **подотрезок** (окно) |
| Указатели могут двигаться навстречу | Оба указателя обычно двигаются в одну сторону |
| Ответ — часто два индекса или свойство | Ответ — длина/сумма/содержимое окна |
| Пример: сумма двух чисел | Пример: максимальная сумма подмассива длины k |

Но граница условна. Некоторые задачи можно решить обоими способами. Главное — понимать смысл указателей, а не спорить о названии.

## 2.8. Мини-практика: определите семейство

Для каждой задачи выберите семейство A, B, C или D. Решения не требуется.

1. Дан отсортированный массив. Удалить дубликаты in-place.
2. Дана строка. Проверить, палиндром ли она.
3. Даны два отсортированных массива. Слить их в один.
4. Дана строка. Найти длину самой длинной подстроки-палиндрома.
5. Дан массив. Переместить все нули в конец, сохранив порядок остальных.
6. Дан отсортированный массив и число `k`. Найти максимальную сумму двух чисел, строго меньшую `k`.
7. Даны две строки. Проверить, является ли первая подпоследовательностью второй.
8. Дан массив. Развернуть его in-place.

## 2.9. Главный вопрос метода

Запомните фразу, которая поможет выводить решения:

> **«Какой вариант я могу перестать рассматривать прямо сейчас и почему?»**

- В быстром/медленном: «этот элемент не нужно сохранять».
- С двух сторон: «с этим краем ответ уже не получится лучше».
- По указателю на массив: «этот элемент меньше, значит он не может совпасть с текущим элементом другого массива».
- От центра: «символы совпали, значит можно расшириться».

Если вы отвечаете на этот вопрос, код пишется почти сам.

## Что запомнить из главы

1. Указатель — это индекс, а не магия.
2. Четыре семейства: быстрый/медленный, с двух сторон, по указателю на массив, от центра.
3. Метод работает за счёт монотонного сужения области поиска.
4. Перед кодом ответьте на семь вопросов: вход/выход, смысл указателей, старт, правило движения, условие остановки, инвариант, границы.
5. Если данные не отсортированы, правило «сумма меньше → left++» может быть неверным.
6. Название приёма менее важно, чем смысл указателей.
