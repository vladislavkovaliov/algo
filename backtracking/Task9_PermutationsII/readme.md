# Task9: PermutationsII

## Паттерн: Бектрекинг (перестановки с дубликатами)

**Зелёные флаги:** перестановки + массив с дубликатами + уникальность результата

## Условие

Дан массив `nums` с дубликатами. Верни все уникальные перестановки.

---

**Постановка:** базовый перебор из Task2 с использованным массивом `used` даст дубли: если в массиве есть два одинаковых числа, перестановки `[1,1,2]` и `[1,1,2]` (первые 1 ↔ втроые 1) посчитаются дважды. Решение — отсортировать и добавить правило пропуска:

```ts
if (i > 0 && nums[i] === nums[i - 1] && !used[i - 1]) continue;
```

**Почему условие именно с `!used[i-1]`?** Мы пропускаем элемент, если его «близнец» слева ещё не использован. Это гарантирует: одинаковые элементы используются в строгом порядке слева направо, значит каждая уникальная перестановка генерируется один раз. (Правило `used[i-1]` тоже работает и даёт другой, но тоже корректный порядок — здесь выбрана классическая версия.)

**Пошагово на примере nums = [1, 1, 2]:**

| Итерация | path | Результат |
|---|---|---|
| 1 | [1(0),1(1),2] | [1,1,2] ✅ |
| 2 | [1(0),2,1(1)] | [1,2,1] ✅ |
| 3 | [2,1(0),1(1)] | [2,1,1] ✅ |

Ответ: `[[1,1,2],[1,2,1],[2,1,1]]`

## Решение

```typescript
export function permuteUnique(nums: number[]): number[][] {
    nums.sort((a, b) => a - b);
    const result: number[][] = [];
    const used: boolean[] = new Array(nums.length).fill(false);

    function backtrack(path: number[]): void {
        if (path.length === nums.length) {
            result.push([...path]);
            return;
        }
        for (let i = 0; i < nums.length; i++) {
            if (used[i]) continue;
            if (i > 0 && nums[i] === nums[i - 1] && !used[i - 1]) continue;
            used[i] = true;
            path.push(nums[i]);
            backtrack(path);
            path.pop();
            used[i] = false;
        }
    }

    backtrack([]);
    return result;
}
```

## Разбор

**Идея:** Task2 + «сортировка и пропуск одинаковых с использованным соседом слева». Отличие от пропуска в SubsetsII — здесь нужен доступ к `used`, потому что перебор идёт не по возрастанию индекса, а по всем позициям сразу.

**Сложность:** O(n·n!) по времени в худшем случае, O(n) по памяти.
