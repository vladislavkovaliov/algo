# Task2: Permutations

## Паттерн: Брутфорс (все перестановки без ограничений)

**Зелёные флаги:** все перестановки, порядок элементов важен, нужны ВСЕ варианты

## Условие

Дан массив уникальных чисел `nums`. Верни **все** возможные перестановки.

---

**Постановка:** перестановки отличаются от подмножеств тем, что длина результата всегда равна длине массива, а каждый элемент используется ровно один раз. Значит, нужен массив `used`, чтобы не брать один элемент дважды. Когда `path` достиг длины nums — это готовая перестановка.

**Почему это Брутфорс, а не Бектрекинг?** Фреймворк §9: «Всё остальное (все комбинации/перестановки без ограничений) → **Брутфорс**». Здесь нет ограничений, которые позволили бы заранее отсечь ветку — нужно просто перебрать все n! перестановок. Отсечения нет, порядок элементов «все, кроме занятых» — не ограничение, а определение перестановки.

**Почему это комбинаторика?** Количество перестановок = n!. Задача «вернуть все варианты».

**Что меняется против Task1:** в Task1 мы ограничивали перебор индексом `start` (элементы строго вперёд). Здесь мы перебираем с нуля каждый раз и блокируем уже взятые элементы через `used`.

**Пошагово на примере nums = [1, 2]:**

| Шаг | used | path | Результат |
|---|---|---|---|
| 1 | - | [] | - |
| 2 | [T,F] | [1] | - |
| 3 | [T,T] | [1,2] | [1,2] ✅ |
| 4 | откат | [1] → [] | - |
| 5 | [F,T] | [2] | - |
| 6 | [T,T] | [2,1] | [2,1] ✅ |

Ответ: `[[1,2], [2,1]]`

## Решение

```typescript
export function permute(nums: number[]): number[][] {
    const result: number[][] = [];
    const used: boolean[] = new Array(nums.length).fill(false);

    function backtrack(path: number[]): void {
        if (path.length === nums.length) {
            result.push([...path]);
            return;
        }
        for (let i = 0; i < nums.length; i++) {
            if (used[i]) continue;
            used[i] = true;
            path.push(nums[i]);
            backtrack(path);
            path.pop();
            used[i] = false;
        }
    }

    backtrack([]);
    return result;
}
```

## Разбор

**Идея:** на каждом уровне рекурсии перебираем все ещё не использованные элементы. Массив `used` гарантирует, что каждый элемент попадёт в перестановку ровно один раз.

**Сложность:** O(n·n!) по времени (n! перестановок, каждую копируем за O(n)), O(n) по памяти для стека рекурсии.
